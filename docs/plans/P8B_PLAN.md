- 状態: **計画（第 2 版、予測帯の式の独立検証を反映。判断 Q7 の確認待ち）**

## P8b の目的（これだけ）

> P8a に合格した候補を、**封印してある最新期間（Holdout）で一度だけ**走らせ、事前に決めた基準で「ここまでの結果と矛盾しないか」を確かめる。実行したら Holdout は**燃える**（二度と使えない）。

P8a は「偶然では説明しにくいか」（統計的な証拠）を確かめた。P8b は、その候補が**将来に一番近い期間でも崩れていないか**を、やり直しのきかない一回で確かめる最後の関門。

### P6 承認時の拘束条件（P8b で必ず守る）

| 拘束条件 | P8b での仕組み |
|---|---|
| 期間の事前固定 | Holdout の期間は P1 から `configs/data_partition.yaml` に固定済み（ワークスペースに記録され、変更すると全実行を拒否）。OOS の対象候補・合格基準・予測帯の**数値**を**マニフェスト**に書いてロックしてから実行する |
| 結果閲覧後のパラメータ変更による汚染管理 | パラメータは候補表の値をそのまま使う。OOS を実行した後に、その戦略ファミリーで作られたラウンドの候補は `HOLDOUT_CONTAMINATED` として OOS に使えない（そもそも Holdout は燃えているので 2 回目は拒否） |
| 再試行の記録 | 技術的な失敗の再実行は**同じジョブ仕様に限り**許し、試行番号を記録する。成功した組は再実行しない。結果の閲覧も記録する |

## 2. 合否の基準（判断 Q2）

設計書 §7.3: 「OOS 利益が最大」ではなく、**ここまでのデータから作った予測分布の下側 5% 点を下回らない**（反証されない）ことを既定とする。OOS 期間は短く分散が大きいので、絶対値ではなく整合性で見る。

| ゲート | 理由コード | 条件（不合格） |
|---|---|---|
| 予測帯 | `OOS_BELOW_PREDICTION_BAND` | OOS の日次 Sharpe が、ロック時に固定した予測帯の下限を下回る |
| 損益 | `OOS_LOSS` | OOS の純損益 ≤ 0 |
| 破綻 | `OOS_RUIN` | 破産・ロスカット |
| コスト耐性 | `COST_FRAGILE` | P8a と同じ追加コスト（`configs/cost_stress.yaml`）を差し引くと OOS の純損益 ≤ 0 |

記録のみ（合否に使わない）: OOS だけで計算した p 値（P8a と同じ方式）、P8a と OOS の成績の差。

### 2.1 予測帯の作り方（ロック時に数値で固定する）

予測帯は**検証期間（P8a）のデータだけ**から作る。Discovery の値は選択による上振れがあるので使わない。

| 量 | 定義 |
|---|---|
| 中心 | 検証期間の日次 Sharpe SR_val（P8a と同じ期間別の集約） |
| 検証期間の標準誤差 se_val | max(√(V / (n_eff − 1)), ブートストラップの SE)。V = 1 − γ₃·SR + (γ₄−1)/4·SR²、n_eff = min(n, AR(1) の n*, Newey-West の n*)（自己相関の補正を含む保守的な値） |
| OOS の予想標準誤差 se_oos | √(V / (n_oos · n_eff / n − 1))。n_oos は Holdout の平日数（実行前に分かる） |
| 下限 | SR_val − 1.645 · √(se_val² + se_oos²)（片側 95%） |

**この下限の数値をマニフェストに書いてロックする**（実行後に計算し直さない）。

### 2.3 予測帯の式の独立検証（2026-10-11 の指摘 ①。`oos_band_check.py`、受け入れ基準は実行前にコミット）

**式の確認（机上）**

| 確認点 | 結論 |
|---|---|
| `n_oos × n_eff / n − 1` の解釈 | 演算の順序どおり (n_oos · n_eff / n) − 1。「OOS の有効サンプル数 n_oos · (n_eff / n)」から 1 を引いたもので、PSR と同じ √(n − 1) の流儀。**意図どおり** |
| n_eff / n の換算と、V0・V1 を独立期間として扱う設計の整合 | AR(1) の n* = n(1 − ρ̂)/(1 + ρ̂) は、共通の ρ のもとで期間ごとの n_j(1 − ρ)/(1 + ρ) の合計と等しい（ρ̂ は期間内の組だけから計算）。Newey-West も期間内の自己相関から f を作り n / f。比 n_eff / n は「自己相関による割引率」で、同じ依存構造なら OOS（1 期間）にも同じ率で当てはまる。**整合している**（Newey-West のラグ数は合計の n から決めるので、期間ごとに決める場合とわずかに違う） |
| V0・V1 の Sharpe と標準誤差の集約 | 期間ごとの Sharpe を平均するのではなく、両期間の日次リターンを 1 つの標本として Sharpe を計算し、標準誤差もその標本の V・n_eff から計算している。期間ごとにボラティリティが違う場合は、混合分布として尖度 γ₄ に反映される。**実測でも正しく集約できている**（下の C3 の「V1 だけボラティリティ 2 倍」） |
| **見つかった不整合** | se_val は max(解析的な値, ブートストラップの SE) だが、第 1 版の se_oos は解析的な n_eff だけで換算していた。ブートストラップの方が大きい（AR(1)・Newey-West が捉えきれない依存がある）とき、se_oos だけ小さくなる。**修正案 fix1**: n_eff* = V / se_val² + 1 として、se_oos = √(V / (n_oos · n_eff* / n − 1))（se_val と同じ補正を se_oos にも使う） |

**C1 手計算**（V0 = [0.010, −0.005, 0.020, 0.000]、V1 = [0.015, −0.010, 0.005]、n_oos = 10）: 平均 0.005、偏差の 2 乗和 700×10⁻⁶ → 標本標準偏差 0.010801 → SR = 0.462910、歪度 0、尖度 1.75、期間内の 1 次自己相関 −425/700 = −0.607143（境界の組 0.000→0.015 は使わない）、V = 1 + 0.75/4 × 0.214286 = 1.040179、n_eff = 7（負の自己相関では縮めない）、se_val = √(1.040179/6) = 0.416369、se_oos = √(1.040179/9) = 0.339964。本番の関数・参照実装と 1e-15 以内で一致 ✅

**C2 独立した参照実装**（numpy も robustlab も使わず、リストとループだけで書き直したもの）: 乱数の 300 データで、最大の相対差 9.7×10⁻¹⁶ ✅

**C3 実測との照合（真の値）**: 真の日次 Sharpe 0.05、各 4,000 回で、SR_oos − SR_val の実際のばらつき（標準偏差）と、式が予想したばらつきを比べた（基準: 予想 ÷ 実測が 0.95〜1.30）。

| 状況 | 実測 | 予想（第 1 版） | 比 | 予想（fix1） | 比 | 判定 |
|---|---|---|---|---|---|---|
| 独立 | 0.05905 | 0.06105 | 1.034 | 0.06137 | 1.039 | ✅ |
| AR(1) 0.4 | 0.09021 | 0.09060 | 1.004 | 0.09085 | 1.007 | ✅ |
| V1 だけボラティリティ 2 倍 | 0.05915 | 0.06131 | 1.037 | 0.06159 | 1.041 | ✅ |
| GARCH ＋ AR(1) 0.4 | 0.08999 | 0.09054 | 1.006 | 0.09084 | 1.009 | ✅ |
| AR(2) 0.3/0.3 | 0.12736 | 0.10541 | **0.828** | 0.11069 | **0.869** | 記録（狭すぎる＝既知の限界） |
| MA(5) | 0.14582 | 0.19674 | 1.349 | 0.19675 | 1.349 | 記録（広すぎる＝保守側） |

→ **式は、想定した依存構造のもとで正しくばらつきを予想している**（誤差 1〜4%、少し広め＝保守側）。fix1 は AR(2) で少し改善し、他はほぼ同じ。

**C4 P8a に合格した候補だけで見た場合（実際の使われ方）— 重要**

P8b に進むのは P8a に合格した候補だけ。**P8a の合格判定と予測帯の中心は、同じ検証期間の Sharpe を使っている**ので、合格した候補の SR_val は偶然上振れした回に偏る（いわゆる「勝者の呪い」）。第 1 版の試算（§2.2 の (a)）は合格したかどうかに関係なく数えていたため、これを見落としていた。

| 状況（本物のエッジが OOS でも続く） | P8a の合格率 | 予測帯を下回る割合（P8a 合格の中で、第 1 版） | fix1 |
|---|---|---|---|
| 独立、日次 Sharpe 0.05（年率 約 0.8） | 32.9% | **13.5%**（11.0〜16.4） | 13.5% |
| 独立、0.08（年率 約 1.3） | 61.1% | **8.3%**（6.8〜10.0） | 8.3% |
| 独立、0.12（年率 約 1.9） | 89.9% | 5.7%（4.7〜6.9） | 5.6% |
| AR(1) 0.2、0.08 | 49.6% | **11.0%** | 11.0% |
| GARCH ＋ AR(1) 0.4、0.08 | 36.1% | **14.3%** | 14.2% |
| AR(2)、0.08 | 31.0% | **23.7%** | 21.9% |

→ **予測帯の計算式は正しいが、中心が上振れしているため、実際の使われ方では本物のエッジを 8〜14% 落とす**（強いエッジ以外で、第 1 版の基準「95% 上限 ≤ 7%」を満たさない）。これは式の誤りではなく、「同じデータで選んで、同じデータで予測する」ことによる偏り。判断 Q7 で対応を決める必要がある（§7）。

## 3. マニフェストと Holdout の解錠・封印

| 項目 | 仕組み |
|---|---|
| 対象 | 1 つの P8a の検証計画（診断ではない）で PASS した候補だけ。0 件ならロックできない |
| ロック | `rlab oos lock <plan_id>` で、候補・予測帯の下限・基準・Holdout の期間（partition のハッシュ）・追加コストを `oos_manifest` 表に保存（追記のみ）。ワークスペースにつき**ロックできるマニフェストは 1 つだけ**（2 つ目は拒否。候補を選び直して OOS をやり直すことを防ぐ） |
| 実行 | `rlab oos run <manifest_id> --i-understand-this-is-final`。フラグがなければ何もしない。Holdout Guard は「ロック済み・未燃焼のマニフェストの候補・Holdout の期間ちょうど」の単一テストだけを許可し、`holdout_access_log` に `approved = 1` とマニフェスト ID を記録 |
| 封印 | 最初の OOS ジョブを開始した時点で `holdout_state = BURNED`（成功しても失敗しても）。以後、Holdout に触れるジョブはすべて拒否。技術的な失敗の再実行だけは、同じマニフェスト・同じジョブ仕様に限り許可 |
| 汚染 | 燃焼後に作られた最適化ラウンドの候補は `HOLDOUT_CONTAMINATED`（OOS の対象にできない。ワークスペースの Holdout はすでに燃えているので、新しい Holdout には新しいワークスペースと新しい partition が必要） |
| 閲覧の記録 | `rlab oos show` のたびに記録 |

**限界（明記する）**: Holdout の燃焼はワークスペースごとの記録で、別のワークスペースを作って同じ期間を Holdout にすることまでは技術的に防げない。`rlab oos lock` の表示と文書で「同じ価格区間を Holdout として使い回さない」ことを明記し、新しいワークスペースでは同じ期間を Holdout にしないよう警告する（設計書 §7.2-6）。

## 4. 練習用ワークスペースでの実機確認（判断 Q3）

- 今の確認用 EA は P7 で選ばれた候補が 0 件で、P8a の PASS もないため、本来の P8b は動かない。**本番の Holdout（2024-07〜2026-06）を確認用 EA で燃やすのは無駄**なので使わない
- そこで**練習用ワークスペース**（`workspace_rehearsal/`）を用意する。partition は練習専用（`configs/rehearsal/data_partition.yaml`、Holdout 2019-01-02〜2019-06-28、`rehearsal: true`）。本番の研究期間（V0 は 2020 年から）とは重ならない
- 練習用ワークスペースでだけ、`--rehearsal --candidate <cd>` で任意の候補のマニフェストをロックできる（本番のワークスペースでは拒否）。結果には `REHEARSAL` と付き、判定は書かない
- 確かめること: マニフェストのロック → 確認フラグなしの実行は何もしない → 一度きりの実行 → BURNED → 2 回目の実行と別マニフェストのロックが拒否される → Holdout Guard の記録
- 練習用ワークスペースにも小さな最適化ラウンドが必要（3 × 3 = 9 パス、2018 年後半、数分）

## 6. テスト・完了条件

### 6.1 事前に固定する検証の条件と合格基準（実装後も同じ条件で評価する）

- 条件: `oos_band.py` と同じ（データの作り方、V0 516 日・V1 115 日・OOS 520 日、各 2,000 回、シード 20261011、ブートストラップ SE は B = 200）。実装後は予測帯の計算を本番の関数に差し替えて、同じ条件で再実行する

- 未達のときは、補正方法・基準・条件を変えずに未達として報告し、判断を仰ぐ（P8a と同じ約束）
- 本番の予測帯の関数が試算と同じ数値を出すことを、同じ乱数で確かめる
