## P2 の目的（これだけ）

> P1 で保存した 1 本のバックテスト結果から、**定義が明確で再現可能な指標**を自前で計算し、MT5 の値との差を説明できる状態にする。

設計書（§3.0 MetricEngine）の方針: MT5 の数値は計算定義が不透明なので、参照値として別に保存し、照合だけに使う。研究で使う値は自前で計算する。

## 1. 調査結果（計画の根拠）

### 1.1 MT5 の指標定義を、手元の実機データで照合した（Claude 側で実施済み）

R1（2026-10-09、EURUSD H1、1 週間）の約定データ `tests/fixtures/hw_20261009/deals.csv` から自前で計算し、同じ実行の MT5 レポートの値と比べた。

| 指標 | 自前の計算 | MT5 レポート | 一致 | 判明した定義 |
|---|---|---|---|---|
| 取引数 | 32 | 32 | ✅ | 決済約定（entry = OUT）の件数 |
| 勝ち / 負け取引 | 16 / 16 | 16 / 16 | ✅ | 決済約定の損益（profit + commission + swap + fee）の符号 |
| 総利益 / 総損失 | 32.01 / −22.32 | 32.01 / −22.32 | ✅ | 同上の合計 |
| プロフィットファクター | 1.43 | 1.43 | ✅ | 総利益 ÷ |総損失| |
| 平均勝ち / 平均負け | 2.00 / −1.40 | 2.00 / −1.40 | ✅ | |
| 期待利得 | 0.30 | 0.30 | ✅ | 純損益 ÷ 取引数 |
| 最大連勝（金額） | 6（5.14） | 6（5.14） | ✅ | 決済約定の時系列での連続 |
| 最大連敗（金額） | 3（−1.23） | 3（−1.23） | ✅ | 同上 |
| 残高最大ドローダウン | 7.43 | 7.43 | ✅ | 約定ごとの残高曲線の最大下落幅 |
| **リカバリーファクター** | 1.30（残高 DD 基準） | **1.91** | ❌ → 解明 | MT5 は **純損益 ÷ 証拠金（エクイティ）最大 DD**（9.69 ÷ 5.07 = 1.91）。エクイティ DD はティック単位の含み損益を含むので、約定データだけでは計算できない |
| シャープレシオ | — | 14.51 | 対象外 | MT5 の計算定義が不明（日次か取引単位か、年率化の有無）。**比較対象にせず、参照値として保存するだけ**にする |

→ 結論: 取引ベースの指標は約定データだけで MT5 と一致する。エクイティ系（エクイティ DD、リカバリーファクター、最大含み損）は、EA 側でティックごとに追跡する必要がある。これが Telemetry 拡張の主な理由。

### 1.2 既存ライブラリの評価（CLAUDE.md の 5 観点）

| ライブラリ | 状態（PyPI, 2026-10-10） | 評価 | 採否 |
|---|---|---|---|
| empyrical | 0.5.5（2020 年で更新停止） | 保守されていない | 不採用 |
| empyrical-reloaded | 0.5.12（2025-06） | リターン系列の指標が中心。PF・連敗・MT5 流の DD 定義は対象外 | 不採用 |
| quantstats | 0.0.86（2026-09、0.0 系） | レポート生成が中心で依存が重い（描画系）。同じく MT5 流の取引指標とは定義が違う | 不採用 |
| **scipy** | 1.18.1 | 歪度・尖度（`scipy.stats.skew` / `kurtosis`）は確立した実装 | **採用**（P6 の PSR/DSR でも使う） |
| **numpy** | 2.5.3 | 配列計算 | **採用** |

- 本基盤で必要な取引指標は「MT5 の定義と一致すること」が要件。既存ライブラリはリターン系列向けで定義が違うため、取引指標は自前で実装し、**MT5 の値をテストの検算基準**にする。
- 統計量（歪度・尖度）は自前で書かず scipy を使う。

## 3. 指標の定義（MetricEngine m1）

詳細な定義は `docs/metrics_definitions.md`（新規）に、バージョン付きで書く。要点:

| 区分 | 指標 | 定義 | MT5 との照合 |
|---|---|---|---|
| 取引 | 取引数・勝ち/負け・総利益/総損失・PF・平均勝ち/負け・期待値・最大連勝/連敗（回数・金額） | 決済約定（entry が OUT または OUT_BY）単位。損益 = profit + commission + swap + fee | 一致を要求（§1.1 で確認済み） |
| 残高 DD | 最大 DD（金額・%）・最大 DD 期間 | 約定ごとの残高曲線 | `STAT_BALANCE_DD` と一致を要求 |
| エクイティ DD | 最大 DD（金額・%） | EA がティックごとに追跡した「エクイティの最高値からの最大下落」 | `STAT_EQUITY_DD` と一致を要求（実機で確認、§5 V2-3） |
| 回復 | リカバリーファクター | 純損益 ÷ エクイティ最大 DD（MT5 と同じ定義。§1.1） | 一致を要求 |
| リスク | 最大含み損、最大ポジション数、最大ロット、最小証拠金維持率、ロスカット約定数、破産フラグ（エクイティ ≤ 0） | EA の追跡値 | MT5 に対応値なし（記録のみ） |
| 日次 | 日次損益、日次リターン、平均・標準偏差、日次シャープ（年率化しない）、歪度、尖度、日数 | 日次損益 = 日終値エクイティの前日比（最初の日は初期資金との差）。**日次リターン = 日次損益 ÷ 初期資金**（固定ロット・複利なしの前提。設計書 §12.1）。標準偏差は標本標準偏差（ddof = 1）。歪度・尖度は scipy（尖度は PSR の式に合わせて「超過でない尖度」を保存） | MT5 のシャープは比較対象外（定義不明） |
| 期間別 | 年別・月別の損益・取引数・最大 DD | サーバ時刻の暦で区切る | — |

- 年率化した値は保存しない（年率化の係数は資産・取引時間で変わるため、使う側で決める）。PSR/DSR は年率化しない値を前提にしている [S-PSR][S-DSR]。
- 指標が計算できない場合（取引 0 件、日数 1 日など）は null を保存し、理由を記録する。

## 4. Telemetry v2 の仕様（MQL5）

- `telemetry_version` を `"2"` にする。v1 で保存済みのジョブも読めるように、Python 側は両方を扱う（v1 ではエクイティ系の指標を null にする）。
- 追加ファイル: `RL_<job>_daily.csv`（日付, 残高終値, エクイティ終値, 日中最小エクイティ, 日中最大エクイティ, 日中最大ポジション数, その日のティック数）
- `env.json` に追加: `equity_peak`, `equity_max_dd`, `equity_max_dd_pct`, `max_floating_loss`, `max_positions`, `max_lots`, `min_margin_level`, `stop_out_deals`
- 追跡は `RL_TelemetryOnTick()` の中で行う（EA 側の変更は不要。P1 と同じ 3 か所の呼び出しのまま）。
- 日の切り替えは、ティックのサーバ時刻の日付が変わったときに前日の行を確定する。最終日の行は `OnDeinit` で確定する。
- ロスカット約定は `DEAL_REASON == DEAL_REASON_SO` で数える（数値の推測をしない）。
- 統計値を追加する（最大連勝・連敗など）: 名前は実機のコンパイルで確認する（§5 V2-1）。

Python 側の整合性チェックに追加するもの:
- 日次の日付が単調増加で重複がない
- 最終日のエクイティ終値 ＝ 初期資金 ＋ 純損益（テスト終了時に全ポジションが決済されるため。実機で確認済み、F4）
- 日中最小 ≤ 終値 ≤ 日中最大

## 10. 承認をお願いしたい判断（要約）

1. **取引指標は自前で実装し、MT5 の値を検算の基準にする**（既存ライブラリは定義が違うため不採用。歪度・尖度は scipy を使う）
2. **リカバリーファクターは MT5 と同じ「純損益 ÷ エクイティ最大 DD」**にする（実機データで確認済み）
3. **MT5 のシャープレシオは比較対象にしない**（定義不明のため参照値として保存のみ）。自前のシャープは日次・年率化なし
4. **日次リターン ＝ 日次損益 ÷ 初期資金**（固定ロット・複利なしの前提）
5. **エクイティ系の値は EA 側でティックごとに追跡する**（Telemetry v2。テストが遅くならないかを実機で確認）
6. **指標は保存済みの原本から計算し、定義のバージョン付きで追記保存する**（バックテストを再実行せずに再計算できる）
7. **P2 では判定をしない**（合否は P4 のゲートの責務）

## 11. 実装メモ（計画からの細部の補足）

| 項目 | 内容 | 理由 |
|---|---|---|
| 連勝・連敗の金額の照合先 | `STAT_MAX_CONPROFIT_TRADES` / `STAT_MAX_CONLOSS_TRADES`（最長の連続の金額）。`STAT_CONPROFITMAX` は「最も利益の大きい連続」で別の値 | MT5 レポートの「最大連勝数（金額）6（5.14）」と「最大連勝利益額（数）8.16（2）」が別の統計であるため。名前と意味は実機の照合で確定する |
| `run_metrics` の形式 | 指標を JSON 列（`metrics_json`）で保存。照合結果・期間別は個別の列 | 指標の追加・定義の版上げのたびに列を変えずに済むため。P4 のゲートで必要になれば、SQLite の JSON 関数で参照できる |
| EA 追跡値の置き場所 | `env.json` の `tracking` オブジェクト | 実行環境の情報と区別するため |
| 最終日の日次エクイティ | `OnDeinit` で、テスト終了時の強制決済後の口座状態に更新してから確定 | 強制決済の手数料などで、最後のティックの値と最終残高がずれるのを防ぐ |
| 指標計算の失敗 | ジョブの成功は取り消さず、警告 `METRICS_FAILED` を記録。`rlab metrics compute` で後から再計算できる | 実行と評価の分離（設計書 §4.1） |
