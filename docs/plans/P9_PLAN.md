## P9 の目的（これだけ）

> P8a に合格した EA について、**資金を守れる最大のロット**を、最大 DD・破産確率・ストップアウト確率の 3 つで上から押さえて決める。ロットが業者の最小ロットに届かなければ **INFEASIBLE** と報告し、**リスクを引き上げて最小ロットに合わせることはしない**。

### 2026-10-11 の指示（P9 で必ず守る 4 原則）

| 原則 | P9 での仕組み |
|---|---|
| ① 資金を守ることを最優先 | ロットは「P(最大 DD > L) ≤ α」「P(破産) ≤ p_ruin」「P(ストップアウト) ≤ p_so」を**すべてのストレスシナリオで同時に満たす最大値**を上限にする（§3）。成長（Kelly）は上限の内側でしか効かない。確率はモンテカルロ誤差を**不利な側に**見る（95% 上側信頼限界で判定） |
| ② 実測の不確実性を反映 | 取引順序のシャッフルに加えて、**連敗・自己相関・ボラティリティ急変・スプレッド拡大・エッジなし（勝者の呪い）とその組合せ**の 8 シナリオ（§2） |
| ③ ロットは合格後に計算 | ロットを出すのは **P8a で PASS（診断モードではない検証計画）**した候補だけ。それ以外は **DIAGNOSTIC**（1 ロットあたりのリスク指標だけ。ロットも判定も出さない）。どちらの画面にも「P9 のシミュレーションで安全に見えても、優位性の証拠ではない」と表示する |
| ④ 実行可能性を厳守 | ロットは常に**切り捨て**。最小ロット未満なら `INFEASIBLE_MIN_LOT`、最小ロットでも証拠金予算を超えるなら `MARGIN_BUDGET_EXCEEDED`。最小ロットへの切り上げ・リスク上限の緩和はコードの経路として**存在させない** |

## 1. 流れ

```
P8a の検証計画（vp_...）で PASS した候補
  → ① 業者情報のスナップショット（Windows、MetaTrader5 API。rlab risk snapshot）
  → ② リスク評価（Linux でも動く。rlab risk run <plan_id> --snapshot <file>）

       8 シナリオ × 10,000 経路 × 252 営業日 → 各経路の「限界ロット」
       → 安全ロット = 全制約を満たす最大ロット（どの制約・シナリオが効いたかを記録）
```

## 2. 入力データとシナリオ

### 2.1 1 ロットあたりの日次系列（リスク単位、設計書 §12.1 (a)）

- 使うのは、その検証計画で走らせた**同じ候補の単体テスト**（`DISCOVERY`・`V0`・`V1`）。各期間は独立した区間として扱い、**区間をまたぐリターンや空白期間のゼロは作らない**（P8a と同じ）。
- **OOS（Holdout）のデータは使わない**（研究上の不変条件。判断 Q4）。
- 日次テレメトリ（`equity_close`・`equity_min`・`positions_max`）と取引履歴から、1 ロットあたりに直す:
  - `x_t` = 終値エクイティの変化 ÷ 取引ロット
  - `d_t` = その日の最安エクイティが「前日終値と当日終値の低い方」より下に潜った幅 ÷ 取引ロット（≤ 0、含み損）
  - `c_t` = その日の決済約定数、`pos_t` = その日の最大ポジション数
- **固定ロットの確認**: 新規約定のロットがすべて同じでなければ `RISK_UNIT_UNDEFINED`（評価しない）。複利で動く EA は DD がロットと絡み合い、この方法では正しく測れないため（設計書 §12.1）。

### 2.2 経路の作り方とシナリオ（すべて 252 営業日、固定ロット、複利なし）

| ID | シナリオ | 作り方 | 何に備えるか |
|---|---|---|---|
| S0 | 基準 | 期間ごとの定常ブートストラップ（ブロック長は Politis-White、`arch`。ブロックは期間の境目をまたがない） | 標本の偶然・ふつうの依存 |
| S1a | 取引順序シャッフル（古典版、**参考指標**） | 取引の決済損益を独立に復元抽出。エクイティは決済の時点でしか見えず、含み損はない | 順序の偶然（標準的な手法として並べて報告。**制約には使わない**、§6.4） |
| S1b | 日単位シャッフル（含み損つき） | 日を独立に復元抽出し、その日の含み損 d_t もいっしょに運ぶ（順序はランダム、含み損は保つ） | 順序の偶然（**制約に使う**。第 1 版の S1 を置き換え） |
| S2 | 連敗 | S0 に、観測された最長連敗日数の 1.5 倍（切り上げ）の負け日（観測された負け日から抽出）をランダムな位置に挿入 | 観測より長い連敗 |
| S3 | 自己相関 | S0 の平均を除いた系列に AR(1) ρ = 0.3 をかける（分散は保ち、長期分散は 1.86 倍） | 損失が続きやすい相場 |
| S4 | ボラティリティ急変 | S0 のランダムな 63 日（約 3 か月）で、平均からの偏差と含み損を 2 倍 | 急な荒れ相場 |
| S5 | スプレッド拡大 | S0 から、決済 1 回ごとに `configs/cost_stress.yaml` の幅の **2 倍**を差し引く（金額換算は業者スナップショットの `order_calc_profit`） | コスト悪化 |
| S6 | エッジなし | S0 から平均を除く | 選ばれた候補の平均は上に偏る（勝者の呪い、P8b C4）。エッジが消えても耐えるか |
| S63 | エッジなし × 自己相関（**Q7 = B で追加**） | S6 の系列に S3 と同じ AR(1) ρ 0.3 | エッジがなく、しかも損失が続きやすい場合（§6.5〜§6.7） |
| SC | 複合 | S6 → S3 → S4 → S2 → S5 を同時に | 悪いことが重なったとき |

- S2〜S6・SC の作り方（倍率・長さ）は本基盤の**独自拡張**（ストレス量は事前に固定した仮定であり、市場で測った値ではない）。標準版として S0（定常ブートストラップ）と S1a（古典的な取引シャッフル）を並べて報告する。
- 乱数のシードは `risk_id` と候補 ID から決め、記録する。

### 2.3 損益・含み損・証拠金の式（k ロットで 252 日持ち続ける）

```
終値エクイティ   E0 + k·C_t,        C_t = x_1 + … + x_t
日中の最安値     E0 + k·M_t,        M_t = C_{t-1} + min(0, x_t) + d_t
DD（終値ピークから）  k·(P_t − M_t) / (E0 + k·P_t),   P_t = max(0, C_1 … C_{t-1})
破産             E0 + k·M_t ≤ (1 − RUIN)·E0          （既定: 開始資金の 50% を失う）
ストップアウト   E0 + k·M_t ≤ SO·k·m·pos_t            （SO = 業者のストップアウト水準、m = 1 ロットの必要証拠金）
```

- 3 つとも、同じ経路の上では k が大きいほど起きやすい（単調）。そのため**経路ごとに「これ以上で限界を超える k」（限界ロット）を式で直接求められる**。「k で限界を超える確率」＝「限界ロットが k 以下の経路の割合」。
- 安全ロットは、その割合の **95% 上側信頼限界（Clopper-Pearson）**が上限以下になる最大の k。モンテカルロの誤差は安全側に使う。
- 近似（記録して表示する）: 含み損の最安値と最大ポジション数が同じ時刻に起きたとみなす（ストップアウトには保守側）。DD のピークは終値ベース。証拠金はスナップショット時点の価格で計算する（XAUUSD のように価格が大きく動いた銘柄では、その後の価格で変わる）。

## 3. 安全ロットとロットの決め方

### 3.1 制約（判断 Q1、提案する既定値。`configs/risk_profiles.yaml`）

| 制約 | 既定値 | 適用するシナリオ |
|---|---|---|
| 最大 DD | P(DD > **20%**) ≤ **5%**（1 年間） | S0・S1b・S2〜S6・S63 のそれぞれ |
| 破産 | P(開始資金の **50%** を失う) ≤ **1%** | S0・S1b・S2〜S6・S63・SC すべて |
| ストップアウト | P(証拠金維持率がストップアウト水準以下) ≤ **1%** | S0・S1b・S2〜S6・S63・SC すべて |

S1a（含み損のない古典的な取引シャッフル）は**参考指標**で、どの制約にも使わない（同じ 20% でも、決済時点だけのエクイティと日中の最安値を含むエクイティは別の量。§6.4）。

- 複合シナリオ SC には DD 制約をかけず、**生き残り（破産・ストップアウト）だけ**を課す。全部が同時に起きる最悪の場合まで DD 20% に抑えると、ほとんどの口座でロットが出なくなるため。SC での DD は表示する。
- 安全ロット `lot_safe` = すべての制約を満たす最大ロット。**効いた制約とシナリオ（例: `SC:ruin`）を必ず記録**する。

### 3.2 配分（設計書 §12.3 の Risk-Constrained Kelly 1 変数版、C10）

```
lot_safe    = §3.1 の最大ロット
lot_kelly   = 0.5 × max(0, μ_LCB) / σ² × E0      （μ_LCB = 1 ロットあたり日次平均のブートストラップ下側 25% 点）
lot_cap     = 0.01 × E0 / （1 取引の損失の 99% 点、1 ロットあたり）     （1 取引で口座の 1% まで）
lot_margin  = 0.30 × E0 / （1 ロットの必要証拠金 × 観測した最大ポジション数）   （証拠金予算 30%）
lot_raw     = min(lot_safe, lot_kelly, lot_cap, lot_margin)    → binding_constraint を記録
lot_target  = lot_raw × confidence_weight × ramp_up
lot         = 最小ロット＋刻みの整数倍に「切り捨て」、最大ロットで頭打ち
```

- `confidence_weight`（判断 Q2）: P8a PASS かつ P8b PASS → 1.0、P8a PASS で P8b 未実施 → 0.5。**P8b で FAIL した候補は配分しない**（`NOT_ELIGIBLE_OOS_FAILED`、リスク指標は DIAGNOSTIC として出す）。
- `ramp_up`: 初回の配分は 0.25（実運用の実績がないため。引き上げは将来の P11 で、人の承認を経て）。
- `μ_LCB ≤ 0` → 配分しない（`NO_ALLOCATION_MU_LCB`）。他の方式で無理に配分しない（設計書 §12.3）。

### 3.3 実行可能性（原則 ④）

| 状況 | 結果 |
|---|---|
| `lot_target ≥ 最小ロット` | `ALLOCATED`。lot は刻みに切り捨てた値（Decimal で計算し、浮動小数の誤差で切り上がらない） |
| `lot_target < 最小ロット` | **`INFEASIBLE_MIN_LOT`**。ロットは 0。「最小ロットで運用するのに必要な口座資金の目安」＝ E0 × 最小ロット ÷ lot_target を表示（参考情報。必要資金を満たしても、自動では配分しない） |
| 最小ロットでも証拠金予算を超える（効いた制約が margin） | **`MARGIN_BUDGET_EXCEEDED`**。ロットは 0 |
| `lot_raw` が 0（μ_LCB ≤ 0） | `NO_ALLOCATION_MU_LCB` |

- 切り上げ・最小ロットへの丸め・上限の緩和は、引数や設定でも行えないようにする（テストで確認）。
- `ALLOCATED` のときは、**最終ロットでの P(DD > L)・P(破産)・P(ストップアウト)・DD の 95%/99% 点をシナリオ別に再計算して表示**する（切り捨て後なので上限より小さいはず。上限を超えていたらバグとして停止）。

### 3.4 RiskProfile（1 ロットあたり、全候補で出す。設計書 §3.9）

シナリオ別に: 最大 DD（金額、1 ロットあたり）の 50%/95%/99% 点、回復期間（DD 開始から新高値まで）の 95% 点と 1 年以内に回復しない割合、連敗数（日数・取引数）の観測値と 95% 点、最大含み損（観測、1 ロットあたり）、証拠金維持率の最小値（観測）。資金の大きさに依存しないので、DIAGNOSTIC でもそのまま出せる。

### 6.1 条件と基準

- **R1 エンジンの正しさ**
  - R1a: 限界ロットの式と、ロットを変えて経路を総当たりで計算した結果が完全一致（60 ケース × 40 ロット）。
  - R1b: 独立同分布の正規日次損益での破産確率と、ブラウン運動の閉形式（Broadie-Glasserman の連続補正）の差 ≤ 4 標準誤差 + 0.003（6 設定）。
  - R1c（**R1b の初回実行後に追加**。R1b の 6 設定が破産確率 45〜80% の領域ばかりで、実際に使う 1% 付近を見ていなかったため）: 破産確率 0.1〜5% の 6 設定、許容 4 標準誤差 + 0.0005。

2. **代わりにロットは小さくなる。** 正常な市場では、真に許される最大ロットの約 55〜63%。これが「資金を守ることを最優先」の代価。実際の配分はさらに信頼度係数（0.5 または 1.0）と立ち上げ係数（0.25）を掛ける。
3. **D5（ボラティリティが恒久的に 1.5 倍になる）は守り切れない。** S4 は「3 か月だけ 2 倍」の一時的な急変で、1 年を通して荒れ続ける体制変化は想定の外にある。超えた幅は小さく（中央値 4.45%、90% 点 5.58%）、破産の制約は 100% 守れているが、基準 90% に対して 73% で**未達**。
4. エッジなし（D6）でも DD の上限を守れているのは、S6（平均を除く）と SC が効いているため。P8b で見つかった勝者の呪い（選ばれた候補の平均は上に偏る）への備えとして働いている。
5. これらは**この仮定の下でのシミュレーションの値**で、実際の EA の将来の確率ではない。

### 6.4 確認 ①: S1（取引順序シャッフル）の DD をどう扱うか（`risk_sim2.py` R3、基準は実行前に記載）

**問題**: 古典的な取引シャッフルは決済損益だけを並べ替えるので、エクイティは決済の時点でしか見えず、含み損が入らない。同じ「DD 20%」でも、日中の最安値を含む DD とは**別の量**で、同じ基準で比べると DD を小さく見積もる。

**整理（第 2 版）**:
- **S1a 古典的な取引シャッフル** → **参考指標**。標準的な手法として結果に並べるが、制約には使わない。
- **S1b 日単位シャッフル（含み損つき）** → **制約に使う**。順序の偶然を調べる役割はそのままに、その日の含み損も運ぶので S0 と同じ量（日中の最安値を含む DD）を測る。

**R3a（記録）**: DD の制約だけで許されるロットの比（1 より大きい = S1a はリスクを小さく見積もる）

| 過程 | S1a ÷ S1b（取引が 1 日で決済） | S1a ÷ S1b（取引が 3 日続く） | S1b ÷ S0 |
|---|---|---|---|
| D1 独立正規 | 1.031 | 1.075 | 0.996 |
| D3 GARCH | 1.031 | 1.078 | 0.995 |
| D4 AR(1) 0.2 | 1.031 | 0.889 | 1.198 |
| D7 AR(2) | 1.032 | 0.818 | 1.449 |

読み方:
1. **S1a はリスクを小さく見積もる**。含み損がないだけで約 3% 多くロットを許し、取引が数日続く（エクイティが見える回数が減る）と、依存のない市場では約 8% 多く許す。ご指摘どおり、同じ基準で制約に使うのは不適切。
2. 一方、自己相関のある市場では、3 日まとめた S1a のほうが厳しくなることもある（まとめた分だけ依存が合計に入るため）。**S1a の甘さ・厳しさは取引の長さと依存の形で変わる**ので、制約としては当てにできない。
3. S1b は順序をランダムにするため依存を壊し、自己相関のある市場では S0 より 20〜45% 甘い。ただし S0 も同時に制約にかかるので、S1b を入れて制約が緩むことはない（効くのは主に独立に近い市場）。

**R3b（基準: 90% / 95%、第 1 版の R2 と同じ）**: 第 2 版のシナリオ構成（S1b を制約、S1a は参考）で R2 をやり直した結果、D1 100%・D2 100%・D3 100%・D4 100%・D6 100% で**合格**。D5 は 78.5% で**未達**のまま（第 1 版 73.0%。Q6 = A の既知の限界）。効いた制約はどの過程でも SC の破産が最多で、S1b が効いた回はなかった。

### 6.5 確認 ②: P8a に即した選抜での「エッジなし」（`risk_sim2.py` R4、基準は実行前に記載）

**問題**: 第 1 版の D6 は「片側 t 検定 5% に合格」で選んだ。実際の P8a は 4 方式の PSR から作る p 値・Holm 補正・利益と追加コストのゲートで選ぶ。また Discovery の履歴は最適化と選抜で選ばれているので、平均がもっと上に偏る。

**R4 の条件**: どこにもエッジがない（真の日次シャープ 0）。
- Discovery 500 日: 独立な 50 候補からシャープ最大のもの（最適化〜P7 の選抜の代わり。**簡略化**: 実際のグリッドの候補は互いに相関し、P7 には他のゲートもある）。
- V0 500 日 + V1 115 日: **本番の P8a の関数**（`robustlab.stats.validation.evidence`、ブートストラップ 2,000 回、期間ごと）で p 値を出し、K = 5 の Holm（他の 4 候補の p 値は一様乱数）、通算の利益 > 0、追加コスト 1 倍を引いても利益 > 0 をすべて満たした履歴だけを使う。
- 基準: 第 1 版の R2 と同じ（真の P(DD>20%) ≤ 5% の回が 90% 以上、破産 ≤ 1% の回が 95% 以上）。

| 過程 | P8a を通過した割合 | 通過した履歴の検証期間シャープ（平均、真は 0） | DD 上限を守れた回（基準 90%） | 真の P(DD>20%) 中央値 / 90% 点 | 破産 ≤ 1% | 判定 |
|---|---|---|---|---|---|---|
| 独立正規 | 0.82% | 0.109 | 99.5% | 2.74% / 3.58% | 100% | 合格 |
| GARCH | 0.79% | 0.109 | 97.5% | 3.12% / 4.35% | 100% | 合格 |
| **AR(1) 0.2** | 1.03% | 0.132 | **62.5%** | 4.60% / 6.06% | 100% | **未達** |

参考: S0 だけで決めると、3 つとも**全回で** DD 上限を破る（真の P(DD>20%) の中央値 40〜47%）。

読み方:
1. **ご指摘どおり、P8a に即した選抜のほうが厳しい。** 第 1 版の D6（t 検定で選抜）では真の P(DD>20%) の中央値が 2.57% だったが、R4 では 2.74〜4.60% まで上がった。実際の P8a 通過者は、t 検定の想定より大きく偏った履歴（検証期間のシャープ 0.11〜0.13）を持ってくる。
2. **自己相関（AR(1) 0.2）があり、かつエッジがない場合に未達。** 破産の制約はすべての回で守れている。超えた幅は中央値 4.60%、90% 点 6.06%。
3. 原因の診断:「通過した履歴は自己相関が弱く見えるものに偏るのでは」という仮説は**否定**された（ラグ 1 の自己相関の平均: 通過 0.191、全体 0.197）。有力な説明は**設計の隙間**。「エッジなし」（S6）と「自己相関」（S3）はそれぞれ単独で DD の制約を受けるが、両方が同時に起きる場合は、DD の制約がない SC（複合、破産・ストップアウトのみ）にしか入っていない。エッジのある市場ではドリフトが DD を和らげるので目立たないが、エッジがないと自己相関による長期の振れがそのまま DD になる。加えて、定常ブートストラップは短いブロックでは正の依存を小さく見積もりやすい。
4. 実際に P8a を通過する候補には、エッジがないのに偶然通った候補が一定の割合で含まれうる（P8b C4、勝者の呪い）。このため、この隙間は**資金配分の対象そのもの**に関わる。

### 6.7 R4 未達の扱い（判断 Q7。合格基準は変えていない）

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A | S63 を足さず、「エッジなし × 正の自己相関 × P8a 通過」を既知の限界として記録・表示（D5 と同じ扱い） | 結果を見てシナリオを足さない | **実際に配分する対象（P8a 通過者）**で守れない場合が残る（試算では 62.5%） |
