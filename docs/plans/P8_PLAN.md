## P8 の目的（これだけ）

> P7 で選んだ候補を、**パラメータを固定したまま**、最適化に一度も使っていない期間で走らせ、「選んだ期間だけの偶然」ではないかを確かめる。

P7 のベンチマークで、P7 は「広がりのある偶然」を落とせない（エッジがなくても 73% の回で何かが選ばれる）ことが分かった。**それを落とすのが P8 の役目**で、P6 の承認（案 A）で「偶然の合格の最終的な抑止は P8 と P10」と決めたのもこのため。

## 1. 提案: P8 を 2 つに分ける（判断 P1）

| | P8a 複数期間検証（今回） | P8b OOS（次回） |
|---|---|---|
| 使う期間 | Validation 期間（Discovery とも Holdout とも重ならない） | Holdout（封印中の最新期間） |
| やり直せるか | 計画を作り直せば再実行できる（ただし回数を記録し、見た期間は「露出」として残る） | **一度きり**。実行したら Holdout は `BURNED`（二度と使えない） |
| 今回の EA で実データ確認 | 診断モード（§6）で可能 | **しない**（エッジのない確認用 EA で Holdout を燃やすのは無駄なので、偽の端末と練習用ワークスペースで確認する） |

分ける理由: OOS は取り返しがつかない操作で、仕組み（マニフェスト・予測帯・封印）も大きい。先に P8a を完成させ、実データで動かしてから P8b の計画を立てる方が安全。**今回の計画は P8a だけを実装対象にする**（P8b は §9 に方針だけ記す）。

## 4. 判定（ゲート。順位はつけない）

設計書 §6.2 の※1: 検証の成績で候補を**並べて上位を採ることはしない**（それをすると検証期間もイン・サンプルになる）。P8a は合否だけを出す。

| ゲート | 理由コード | 条件（不合格） | 根拠 |
|---|---|---|---|
| 再現性 | `REPRODUCIBILITY_MISMATCH` | Discovery 期間の単一テストの純損益・取引数が、P3 の最適化パスと一致しない（P3 の x8 確認と同じ照合） | 同じ設定で結果が違えば、どの数字も信用できない |
| 破綻 | `BANKRUPTCY` / `STOP_OUT` | 検証期間のどれかで破産・ロスカット | P4 と同じ |
| 検証期間の損益 | `VALIDATION_PERIOD_LOSS` | 検証期間を合わせた純損益 ≤ 0 | 設計書 §3.7 |
| **統計的な証拠**（判断 P3） | `VALIDATION_INSUFFICIENT_EVIDENCE` | §4.2 の p 値が Holm 法（全体で片側 5%）で有意でない。**表示は「証拠不足（エッジがないという意味ではない）」** | §4.1・§4.2 |
| コスト耐性 | `COST_FRAGILE` | §4.3 の追加コスト（1 倍）を決済ごとに差し引くと、検証期間を合わせた純損益 ≤ 0 | 設計書 §9.2、C60 |

警告（合否に使わない）: 期間ごとの赤字（`VALIDATION_PERIOD_LOSS_SINGLE`）、上位 5 取引を除くと純損益 ≤ 0（`PROFIT_CONCENTRATED`）、自己相関が強い（`SERIAL_DEPENDENCE_HIGH`）、追加コスト 0.5 倍での結果（記録）、`VALIDATION_REVISED`・`SELECTION_REVISED`。

### 4.1 統計的な証拠のゲートが必要な理由と、その性能（実装前の試算）

**なぜ必要か**: 「検証期間で黒字」だけを条件にすると、エッジのない戦略でも約半分が通る（黒字か赤字かは五分五分）。P7 はエッジがなくても 73% の回で何かを選ぶので、黒字だけの条件では偶然がそのまま P8 を通ってしまう。検証期間は選抜に一度も使っていない初めてのデータなので、**ここで統計的に偶然を退ける**のが P8 の本来の役目（P6 の案 A で DSR を合否に使わないと決めた代わりの、最終防衛線の 1 つ）。

**ゲートの中身**: 候補ごとに、検証期間を合わせた日次リターンの PSR(0) を P6 と同じ 4 方式（標準・AR(1) の n*・Newey-West の n*・ブートストラップの標準誤差）で計算して最小値をとり、p = 1 − PSR とする。選ばれた候補の数 K について **Holm 法**（全体で 5%）で有意なものだけを通す。

**実装前の試算**（`docs/research/p8_simulations/validation_gate.py`、検証 630 日、各 2,000 回、シード 20261011、Clopper-Pearson の 95% 区間）:

偶然の合格率（エッジのない候補が 1 つでも通る割合。基準は P6 と同じ「95% 上限 ≤ 7%」）:

| 状況 | 結果 | 判定 |
|---|---|---|
| K = 1、独立 | 4.0%（3.2〜5.0） | ✅ |
| K = 1、AR(1) 0.4 | 4.45%（3.6〜5.5） | ✅ |
| K = 1、AR(2) 0.3/0.3 | 6.5%（5.5〜**7.7**） | ❌ 既知の限界（P6 と同じ） |
| K = 1、MA(5) | 1.4%（0.9〜2.0） | ✅ |
| K = 1、GARCH ＋ AR(1) 0.4 | 4.3%（3.5〜5.3） | ✅ |
| K = 5（候補どうしの相関 0.5）、独立 | 3.25%（2.5〜4.1） | ✅ |
| K = 5（相関 0.5）、AR(2) | 8.1%（6.9〜**9.4**） | ❌ 既知の限界 |

検出力（本物のエッジを持つ候補が通る割合。日次 Sharpe 0.05 / 0.08 / 0.12 ＝ 年率でおよそ 0.8 / 1.3 / 1.9）:

| 状況 | 0.05 | 0.08 | 0.12 |
|---|---|---|---|
| K = 1、独立 | 33% | 61% | 90% |
| K = 5（他の 4 つはエッジなし）、独立 | 13% | 36% | 72% |
| K = 5、AR(1) 0.2 | 10% | 25% | 55% |

**読み取れること**:
- 偶然の合格はよく抑えられる（3〜4.5%）。ただし AR(2) 型の依存では 6.5〜8.1% で、P6 と同じ**既知の限界**が残る（結果に明示する）
- **検出力は低い。** 検証期間 630 日では、年率 Sharpe 1.3 程度の本物のエッジでも、候補が 5 つなら 3 つに 1 つしか通らない。これはデータの長さによる限界で、手法の欠陥ではない。P7 で選ばれる件数が少ないほど（Holm の補正が軽くなり）、検証期間が長いほど上がる
- つまり P8a を通る候補は「偶然では説明しにくい」が、**落ちた候補が「エッジがない」とは言えない**。理由コードは `VALIDATION_INSUFFICIENT_EVIDENCE`、表示は「証拠不足（エッジがないという意味ではない。検証期間の長さでは偶然と区別できなかった）」とする

### 4.2 統計ゲートの定義（P3 の条件に対する事前固定）

| 項目 | 固定する内容 |
|---|---|
| 帰無仮説・対立仮説 | 候補ごとに H0: 検証期間の日次リターンの真の Sharpe ≤ 0、H1: > 0（**片側**） |
| 入力の系列と集約 | **§4.2.1 のとおり、V0 と V1 は別々の独立した期間として扱う**（つなげて 1 本の時系列にはしない） |
| 自己相関補正後の p 値 | **p = 1 − min(PSR_標準, PSR_AR(1), PSR_Newey-West, PSR_ブートストラップ SE)**、SR* = 0。各 PSR は P6 と同じ式・同じ規則（AR(1) は ρ̂₁ > 0 のときだけ、Newey-West は f > 1 のときだけ n を縮める）。ただし自己相関とブートストラップは §4.2.1 の期間別の計算に置き換える。ブートストラップは B = 2,000、シード = sha256(plan_id｜candidate_id) の先頭 8 桁。計算できない方式は最小値から除く。**標準の PSR も計算できない（合計の日数 < 30、分散 0 など）ときは p = 1**（証拠なし）。この p 値が依存関係のもとでも妥当かは §4.4 の独立した検証で確かめる |
| Holm 法の適用単位（家族） | **同じ選抜（`sel_id`）について、それまでにロックしたすべての検証計画に含まれた候補の和集合**。K = その異なる候補の数。計画を作り直しても K は減らない（作り直しで補正を軽くできないようにする）。他のゲートで落ちた候補・技術的に失敗した候補も K に数える（保守側） |
| 有意水準 | 家族全体で **α = 0.05**（片側） |
| Holm の手順 | 家族の p 値を小さい順（同じ値は candidate_id の辞書順）に p₍₁₎ ≤ … ≤ p₍K₎ と並べ、i = 1 から順に p₍ᵢ₎ ≤ α / (K − i + 1) なら有意、最初に満たさなかったところで止め、それ以降はすべて有意でない。まだ結果のない候補の p は 1 として扱う（その候補の結果が出たら判定をやり直し、新しい判定として追記する） |
| 診断モード | K = 1 で計算し表示するが、判定（decision）は書かない |
| 既知の限界 | AR(2) 型の依存では偶然の合格率が 6.5〜8.1%（§4.1）。結果の表示に毎回出す |

#### 4.2.1 複数期間の集約方法（2026-10-11 の指摘 2 に対する事前固定）

V0 と V1 は、**それぞれ初期資金 D から始まる独立した単一テスト**として扱う。期間の境界をまたぐリターンや、空白期間（V0 の終わりから V1 の始まりまで）のゼロリターンは**作らない**。

| 統計量 | 集約方法 |
|---|---|
| 日次リターン | 期間 j ごとに r_{j,t} = (E_{j,t} − E_{j,t−1}) / D、E_{j,0} = D。期間 j の最初のリターンは、その期間の初期資金に対する初日の損益（前の期間の最終値とは結ばない） |
| 標本 | 両期間の日次リターンを集めた**標本**（n = n₀ + n₁）。並び順は意味を持たない |
| 平均・標準偏差・Sharpe | 標本全体の平均、標本標準偏差（ddof = 1）、その比（年率化しない） |
| 歪度・尖度 | 標本全体からモーメント法で（P6 と同じ） |
| 自己相関 ρ̂_k | **期間の中の組だけ**を使う: ρ̂_k = Σ_j Σ_{t>k}(r_{j,t} − r̄)(r_{j,t−k} − r̄) ÷ Σ_j Σ_t (r_{j,t} − r̄)²（r̄ は標本全体の平均）。期間をまたぐ組（V0 の最後と V1 の最初）は数えない |
| AR(1) の n*・Newey-West の n* | 上の ρ̂_k から P6 と同じ式で。Newey-West のラグ数 L = ⌊4(n/100)^{2/9}⌋（n は合計） |
| ブートストラップの標準誤差 | **期間ごとに別々に**定常ブートストラップ（平均ブロック長は期間ごとに Politis-White、1 未満は 1）で元の長さの再標本を作り、両期間の再標本を集めて Sharpe を計算する。これを B 回繰り返した標準偏差（ブロックは期間をまたがない） |
| 損益・破綻・コスト | 純損益は期間ごとの合計。破綻は期間ごとに判定。追加コストは期間ごとに差し引いて合計 |
| 期間ごとの値（表示） | 期間ごとの Sharpe・純損益・取引数も記録し、`VALIDATION_PERIOD_LOSS_SINGLE`（警告）の判定に使う |

理由: 2 つの期間は約 2 年離れていて、最後の日と最初の日をつなぐと存在しないリターン（またはゼロのリターン）ができ、平均・分散・自己相関・ブートストラップのブロックがその作り物に影響されるため。

### 4.4 p 値の妥当性と Holm 法の検証（2026-10-11 の指摘 1。実装前に実行する）

Holm 法は「各候補の p 値が妥当（帰無仮説のもとで P(p ≤ u) ≤ u）」であれば、候補どうしの依存のしかたによらず家族全体の誤り率を α 以下に保つ（Holm 1979）。そこで、**(1) p 値そのものの妥当性**、**(2) Holm 法の実装の正しさ**、**(3) Holm 法を通したときの家族全体の誤り率**を、別々のテストで確かめる。

| # | 検証 | 方法 | 合格基準（事前に固定） |
|---|---|---|---|
| H1 | p 値の妥当性（K = 1、真の Sharpe がちょうど 0） | §4.2.1 の集約で p 値を計算し、u = 0.01・0.025・0.05・0.10 のそれぞれで P(p ≤ u) を数える。状況: 独立、AR(1) 0.4、MA(5)、GARCH ＋ AR(1) 0.4、V1 だけボラティリティ 2 倍（独立）、AR(2) 0.3/0.3。**各 10,000 回**（u = 0.01 でも判定できる回数） | 各 u で **95% 上限 ≤ 1.4 × u**（u = 0.05 で 7%、P6 と同じ考え方）。AR(2) は既知の限界として記録 |
| H2 | Holm 法の実装 | 自前の Holm 法の結果を、独立に書かれた実装（statsmodels 0.15.0 の `multipletests(method="holm")`）と比べる。乱数で作った 10,000 組の p 値（K = 1〜8、同じ値・境界の値を含む）と、手計算の例 | **すべての組で有意・非有意が完全に一致** |
| H3 | 家族全体の誤り率（K = 5、すべてエッジなし） | 候補どうしの相関 0.5 と 0.9、独立・GARCH ＋ AR(1) 0.4・AR(2)。各 2,000 回 | 95% 上限 ≤ 7%。AR(2) は既知の限界として記録 |
| H4 | 検出力 | K = 5（1 つだけ日次 Sharpe 0.05・0.08・0.12、他の 4 つはエッジなし、相関 0.5）の独立・AR(1) 0.2、K = 1 の独立 | 記録のみ |

条件（固定）: n₀ = 516（V0）、n₁ = 115（V1）を**別々に生成**（GARCH の状態も期間ごとに初期化）、シード 20261011、ブートストラップ SE は各回 B = 200、Clopper-Pearson の 95% 区間。スクリプト: `docs/research/p8_simulations/validation_gate2.py`（第 2 版の `validation_gate.py` は 1 本につないだ系列で計算していたため、参考として残し、判定には使わない）。

H1 p 値の妥当性（K = 1、各 10,000 回。表は P(p ≤ u)、括弧は 95% 区間、基準は上限 ≤ 1.4u）:

| 状況 | u = 0.01（上限の基準 0.014） | u = 0.025（0.035） | u = 0.05（0.070） | u = 0.10（0.140） | 判定 |
|---|---|---|---|---|---|

### 4.3 追加コストの定義（P4 の条件に対する事前固定。XAUUSD を含む）

**「pip」は使わない。** 銘柄によって pip の意味が違い（FX の 5 桁表示では 10 ポイント、XAUUSD では業者により 0.1 ドルとも 0.01 ドルとも言われる）、取り違えると桁が 10 倍ずれるため。追加コストは**価格の幅**（その銘柄の値段の単位）で銘柄ごとに固定する。

```yaml
# configs/cost_stress.yaml（新規。内容のハッシュを検証計画に含める）
symbols:
  EURUSD: {extra_price_per_round_trip: 0.00010}   # 価格で 0.00010（5 桁表示で 10 ポイント、一般に 1 pip）
  XAUUSD: {extra_price_per_round_trip: 0.30}      # 価格で 0.30 ドル/オンス（2 桁表示で 30 ポイント）
```

| 項目 | 固定する内容 |
|---|---|
| 値の根拠 | 「通常のスプレッドとおよそ同じ幅をもう 1 回払う」程度の悪化を想定（EURUSD は 0.6〜1.0 pip 程度、XAUUSD は 0.15〜0.35 ドル程度が一般的なスプレッドの目安）。**仮定であり、ブローカーで確かめた値ではない**。実機確認で、テレメトリが記録したスプレッド（観測値）と並べて表示する |
| 対象の銘柄 | `cost_stress.yaml` にない銘柄の検証計画は**ロックを拒否**する（既定値で黙って計算しない） |
| 金額への換算 | 1 回の決済の追加コスト = 価格の幅 ÷ `tick_size` × `tick_value` × 決済の数量（ロット）。`tick_size`・`tick_value` はテレメトリが記録した銘柄仕様（その単一テストのもの）。例: EURUSD・口座 USD（tick_size 0.00001、tick_value 1.0）で 0.01 ロット → 0.00010 ÷ 0.00001 × 1.0 × 0.01 = 0.10 USD。XAUUSD・口座 USD（tick_size 0.01、tick_value 1.0、1 ロット = 100 オンス）で 0.01 ロット → 0.30 ÷ 0.01 × 1.0 × 0.01 = 0.30 USD |
| 換算の限界 | 決済通貨（クオート通貨）と口座通貨が違う銘柄では `tick_value` が為替で変わるが、テスト終了時の値で一律に換算する（近似）。その旨を結果に記録する |
| 既存コストとの重複 | テスターの損益には、**スプレッド（実ティックの売値・買値）・手数料・スワップ・その他の費用（fee）がすでに含まれている**。追加コストはそれらを差し引き直したり置き換えたりせず、**上乗せ分だけ**を差し引く（滑りやスプレッドの拡大を想定した上乗せ） |
| 損益への適用 | 売買の約定のうち**決済の約定（entry = OUT / INOUT / OUT_BY。P2 の指標と同じ決済の定義）ごとに 1 回**、その約定の数量で差し引く（往復で 1 回。部分決済は約定ごとに数量に比例）。エントリーの約定には適用しない。検証期間を合わせた純損益から差し引いた値で `COST_FRAGILE` を判定する |
| 統計ゲートとの関係 | 追加コストは `COST_FRAGILE` の判定（と 0.5 倍の記録）にだけ使い、§4.2 の日次リターン・p 値には適用しない（二重に厳しくしない） |
| 利益集中（警告） | 決済の約定ごとの損益（profit ＋ commission ＋ swap ＋ fee）の上位 5 件を除いた合計 ≤ 0 なら `PROFIT_CONCENTRATED` |

## 5. 露出台帳と汚染管理

| 仕組み | 内容 |

| 露出の記録 | 検証ジョブの結果を保存した時点で、`(戦略ファミリー, 期間)` を `period_exposure` 表に記録する（追記のみ。最初に見た日時、どの計画か） |

| 診断モードの扱い | 診断の結果は判定に使わず、診断の計画を本番の計画に切り替える手段も作らない（診断で結果を見た候補を本番で検証するには、新しい計画のロックが必要で、作り直しとして記録される） |
