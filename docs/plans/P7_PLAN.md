## P7 の目的（これだけ）

> P4（足切り）・P5（ロバストネス）・P6（統計）の結果をまとめて、候補ごとに「次の段階（P8: 新しい期間での検証）へ進めるか」を**理由コード付きで判定**し、進める候補を**上限数（予算）以内**で選ぶ。

P7 は**合否と選抜を決める最初の段階**です。ここで決めた候補だけが P8 に進みます。P7 で使うのは Discovery 期間（候補を選んだ期間）の値だけで、P7 の判定は「将来も儲かる」ことの証拠ではありません（§5）。

## 3. 判定と選抜の仕様案

### 3.1 全体の流れ（設計書 §11.3 の推奨構成を、今使えるデータに合わせたもの）

```
P4 合格の候補（それ以外は P7 の対象外。件数だけ表示）
  → ① ゲート（合否、理由コード付き）: 孤立した合格点・孤立したピーク・近傍の不足・近傍の不安定（§3.2）
  → ② 領域ごとに代表を 1 つ（§3.5-1）
  → ③ 統合順位（§3.5-2）: パレートの層 → 層の中は 3 つの物差しの「順位の平均」 → 決められた同点処理
  → ④ 予算 K（既定 5）まで、統合順位の上から採る
  → SELECTED / NOT_SELECTED（理由: REDUNDANT_IN_REGION・DOMINATED・NOT_SELECTED_BUDGET）/ FAIL（ゲートの理由）
```

### 3.2 ゲート（① 合否を決めるもの。すべての候補に全ゲートを評価し、最初の不合格で止めない）

#### 3.2.1 近傍の数え方（R3 の条件に対する事前固定。**独自拡張**）

近傍 = グリッド上でチェビシェフ距離 1 のセル（P5 と同じ。グリッドの外は数えない）。各近傍セルの P5 の `score_status` で次のように扱う。

| 近傍の状態 | 扱い | 理由 |
|---|---|---|
| `OK` | 数える（値 = 日次 Sharpe） | — |
| `NO_TRADES`（取引なし） | **数えない**（グリッドの外と同じ） | 取引しないのは損失ではなく「その設定では何もしない」。P3 の EA のように無効な組合せを取引なしで走らせる EA で、境目の候補を不当に落とさない |
| `BANKRUPTCY` / `STOP_OUT`（破産・ロスカット） | **数える（値 = −∞）。さらに 1 つでもあれば `NEIGHBORHOOD_UNSTABLE` で不合格** | 少しずれると破産する設定は危険（承認条件どおり判定の対象に含める） |
| `NOT_COMPUTABLE` | 数える（値 = −∞） | 計算できない理由が分からないので、保守的に悪い値として扱う |

- **数えた近傍の数（自分を除く）の下限: ⌈(3^d − 1) / 2⌉**（2 次元なら 8 の半分で 4、3 次元なら 26 の半分で 13）。P5 の `EDGE`（近傍が全体の半分未満）と同じ境目
- **下限に満たないときは不合格（理由コード `NEIGHBORHOOD_INSUFFICIENT`）**。周りの成績が分からない候補は、ロバストかどうか判断できないため次の段階に進めない。グリッドの角（2 次元で近傍 3）もこれで落ちる（最良の設定が探索範囲の角にあるのは、範囲が狭すぎる兆候）
- P5 の値（取引なしも −∞ に含めた Robust Score）と、この数え方で計算し直した値の両方を判定に記録し、並べて表示する（標準版と独自拡張を並べる約束）

#### 3.2.2 ゲートの一覧

| ゲート | 理由コード | 条件（不合格） | 既定値 | 根拠 |
|---|---|---|---|---|
| 孤立した合格点 | `ISOLATED_PEAK` | 隣に P4 合格が 1 つもない（P5 の `region_status = ISOLATED_PASS`） | — | 設計書 §9.3・§11.3 |
| 近傍の不足 | `NEIGHBORHOOD_INSUFFICIENT` | 数えた近傍が下限未満（§3.2.1） | ⌈(3^d−1)/2⌉ | R3 の条件 |
| 近傍の破産 | `NEIGHBORHOOD_UNSTABLE` | 近傍に破産・ロスカットが 1 つでもある | — | 設計書 §9.2 |
| 近傍の不安定 | `NEIGHBORHOOD_UNSTABLE` | 自分と数えた近傍の値の 25% 分位点（`inverted_cdf`、P5 と同じ）≤ 0 | 0 | 「周りが悪い」＝少しずれると負ける |
| 孤立したピーク | `ISOLATED_PEAK` | 自分 ÷ 数えた近傍の中央値 > 1.5。中央値 ≤ 0 なら比が意味を持たないが、自分はプラス（P4 合格）で周りが 0 以下なので**ピークとみなして不合格** | 1.5 | 設計書 §9.2 の例示値、C56 |

### 3.3 警告（記録するが合否には使わない）

| 警告コード | 条件 | 出どころ |
|---|---|---|
| `LOW_DSR` | 保守的な DSR < 0.95 | P6 |
| `SERIAL_DEPENDENCE_HIGH` | n / n* ≥ 1.5 | P6 |
| `SHARPE_CI_INCLUDES_ZERO` | ブートストラップの Sharpe 90% 区間が 0 を含む | P6 |
| `BOOTSTRAP_SENSITIVITY` | 循環ブロックと定常ブートストラップの区間幅が大きく違う | P6 |
| `EDGE` | グリッドの外を含めて近傍が全体の半分未満（P5 の値） | P5 |
| `NO_TRADE_NEIGHBOURS` | 近傍に取引なしがあり、§3.2.1 で数えなかった | R3（どれだけ除いたかを残す） |
| `SUBPERIOD_INCONSISTENT` | 黒字の年の割合 < 0.5、または最悪年がマイナス | P5（2 年分しかないので、合否には使わない） |
| `TRADE_FREQUENCY_OUT_OF_PROFILE` | P4 の警告を引き継ぐ | P4 |
| `RANK_INPUT_MISSING` | 統合順位の物差しのどれかが欠けている（§3.5-2） | P6 |

### 3.4 DSR の使い方（P6 承認条件 1 と R4 の条件）

1. **DSR は合否に使わない。** ゲート（§3.2）に DSR は出てこない。`LOW_DSR` は警告コードだけに入り、理由コード（`reason_codes`）には入らない
2. **DSR は相対順位にだけ使う。** 使うのは「候補どうしで比べた順位」だけで、DSR の値を閾値（例: 0.95 以上）と比べることは選抜でもしない
3. 順位づけの方法と同点処理は §3.5-2 に事前固定する（DSR は 3 つの物差しの 1 つで、重みは他と同じ 1/3）
4. テストで保証すること:
   - 全判定の `reason_codes` に DSR 由来のコードがない
   - DSR の値だけをどう変えても、各候補のゲートの結果（FAIL か、ゲート合格か）は変わらない
   - DSR の値をそのまま定数倍・単調変換しても、選ばれる候補と順位は変わらない（＝値ではなく順位だけを使っている）

### 3.5 代表・統合順位・予算（②③④。R5 の条件に対する事前固定）

#### 3.5-1 領域の代表（②）

- 領域 = P5 の領域（P4 合格セルの連結成分）。代表は**ゲートに合格した領域内の候補のうち、メドイドへのチェビシェフ距離が最小のもの**（メドイド自身が合格ならメドイド）。同じ距離なら §3.5-2 の統合順位が上の方、それも同じなら candidate_id の辞書順
- 代表以外のゲート合格候補は `NOT_SELECTED`（理由 `REDUNDANT_IN_REGION`）

#### 3.5-2 統合順位（③）

物差しは 3 つ。**どれも「値の大きさ」ではなく「候補どうしの順位」だけを使うので、尺度の違い（Sharpe と確率と金額）は結果に影響しない。**

| 物差し | 良い方向 | 比べる前の丸め（浮動小数点の誤差で順位が揺れないように） |
|---|---|---|
| Robust Score（§3.2.1 の数え方で計算し直した値） | 大きいほど良い | 小数 9 桁 |
| 保守的な DSR（P6） | 大きいほど良い | 小数 9 桁 |
| 再標本化した最大 DD の 95% 点（P6、日末エクイティ、口座通貨） | **小さいほど良い** | 小数 2 桁（セント） |

手順（すべて決定的）:
1. **欠けた値**（例: DSR が計算できない）は、その物差しで最も悪い値として扱い、警告 `RANK_INPUT_MISSING` を付ける
2. **パレートの層**: 最大 DD は符号を反転して「大きいほど良い」にそろえ、「3 つすべてで同等以上、かつ 1 つ以上で上回る」候補がいれば負けとする。どの候補にも負けていない候補が第 1 層、それを除いて負けていない候補が第 2 層 … （層は尺度に依存しない）
3. **層の中の並べ方**: 各物差しで代表どうしの順位をつける（1 位が最良。同じ値は平均順位）。3 つの順位の**単純平均**（重みは等しく 1/3）が小さい順
4. **同点処理**（平均順位も同じとき）: ① Robust Score の順位が上 → ② 最大 DD の順位が上 → ③ DSR の順位が上 → ④ candidate_id の辞書順。DSR を後ろに置くのは、DSR の影響を「相対順位の 1 要素」にとどめるため
5. 統合順位 = 第 1 層の並び → 第 2 層の並び → …

- 層を使う理由: 3 つすべてで負けている候補を、平均順位のたまたまの良さで上に置かないため（設計書 §11.2 のパレート）
- 平均順位を使う理由: 設計書の「混雑距離」（NSGA-II）は物差しの空間での多様性を見るが、パラメータの多様性は ② の領域代表ですでに確保している。順位の平均は尺度に依存せず、説明しやすく、決定的（設計変更 C68 として記録）

#### 3.5-3 予算と理由コード（④）

| 項目 | 内容 |
|---|---|
| 予算 K | 全体 5、同じ領域から 1（代表だけなので自動的に満たす） |
| 採り方 | 統合順位の上から K 件を `SELECTED`。選ばれた順位を記録する |
| 選ばれなかった代表の理由 | 選ばれた候補のどれかに負けている（パレートの意味で）→ `DOMINATED`。それ以外 → `NOT_SELECTED_BUDGET` |
| 再現性 | 入力の並び順・ハッシュの順序によらず、同じ入力なら同じ選抜・同じ順位・同じ ID（テストで確認、§6.2） |

### 3.6 事前登録と「選び直し」の記録（設計書 §11.4）

- 閾値・予算・物差し・Selector 名は `configs/selection_profiles.yaml`（新規）に置き、内容のハッシュを判定に記録する。値を変えると別の実行として記録され、古い判定は書き換えない
- 同じラウンドで、**違う設定・違う Selector で選び直した回数**を数えて表示し、2 回目以降には警告 `SELECTION_REVISED` を付ける。P8 では、どの選抜結果を使ったかを記録する（P8 の計画で扱う）
- Selector は既定の 1 種類（`region_pareto_v1`）だけを CLI から使えるようにする。比較用の単純な Selector（P4 合格を Robust Score 順に上位 K、`hard_gate_v1`）はベンチマーク（§6）の中だけで使う。**選択肢を増やすこと自体が Selector の過学習を招く**（設計書 §21.3）

## 5. データの独立性（P8 と混同しない）

- P7 が読むのは、そのラウンドの FILTER（P4）・ROBUSTNESS（P5）・STATISTICS（P6）の評価値だけ。どれも Discovery 期間の値
- 設計書 §6.2 の※1: P8 の検証結果を P7 の選抜に戻すと、検証期間もイン・サンプルになる。P8 で落ちた候補の代わりに P7 の次点を繰り上げることは、**新しい選抜として記録**し（`SELECTION_REVISED`）、P8 の計画で回数を数える
- 表示に「Discovery 期間の値で選んだ結果で、将来の成績の予測ではない」と注記する

## 6. テスト

### 6.1 合成グリッドでの Selector のベンチマーク（設計書 §19.4、合格基準は事前に固定）

30 × 30 のグリッドに、なめらかなノイズ（相関のある偶然の山）を置き、条件ごとに 500 回（シード 20261011）。実装後は本番の関数（ゲート・代表・統合順位）で実行する。

| シナリオ | 内容 | 合格基準（事前に固定） | 実装前の試算（500 回） |
|---|---|---|---|
| A: 本物の台地 ＋ 偶然の尖り | 6 × 6 の台地（真のスコア +0.08）と、孤立した尖り 3 つ（0.15） | `region_pareto_v1` が台地の候補を選ぶ割合の 95% 下限 ≥ 90%、尖りを選ぶ割合の 95% 上限 ≤ 5% | 台地 100%、尖り 0% |
| A の比較 | 素朴な方法（生のスコア最大の 1 点）・`hard_gate_v1` | 記録のみ | 素朴な方法は **99.8% で尖りを選ぶ**。`hard_gate_v1` は台地 99.6%・尖り 0% |
| B: 尖りだけ（台地なし＝エッジなし） | 偶然の山と尖り 3 つ | 尖りを選ぶ割合の 95% 上限 ≤ 5%。**何かが選ばれる割合を重要指標として記録** | 尖り 0%、**何かが選ばれる 73%**（`hard_gate_v1` は 45% で尖りを選ぶ） |
| C: ノイズだけ（エッジなし） | 偶然の山だけ | **重要指標として記録**（合否の基準は置かない。パイプライン全体の偶然の合格率の基準は P10 で決める） | **何かが選ばれる 73%**（平均 1.1 件） |

**重要指標: エッジなしの条件（B・C）で候補が選ばれる割合（承認時の指示）**
- 「1 件以上選ばれた回の割合」（Clopper-Pearson の 95% 区間つき）と「1 回あたりの選ばれた件数の平均・分布」を記録し、結果の文書（`docs/research/p7_validation/RESULTS.md`）の最初に載せる
- CLI の選抜結果の表示にも、この値と「P7 で選ばれたことはエッジの証拠ではない」という注記を毎回出す
- 合否の基準を置かない理由: この値は「P7 だけでは偶然を落とせない」ことを示すもので、下げる責任は P8・P10 にある。基準を置くと、この値を下げるために P7 の閾値を合成データに合わせ込む誘因になる

試算の条件: P4 の合格を「スコア > 0.05」、DSR を「スコアの大きさ」、最大 DD を乱数で代用した簡易版（`docs/research/p7_simulations/proto.py`。統合順位は第 1 版の並べ方）。

**試算から分かったこと（大事）**:
- 領域の代表を選ぶ方法は、**孤立した尖り（偶然の当たり）を確実に避ける**。生のスコアで最大の 1 点を選ぶ（MT5 の最適化結果を上から選ぶ）と、ほぼ必ず尖りを選んでしまう
- 一方で、**なめらかな偶然の山（隣どうしが似た成績になるノイズ）は、本物の台地と区別できない**（エッジなしでも 73%）。最適化のパスは隣どうしが強く相関しているので、偶然でも「台地のような形」ができる。P7 の選抜は「孤立した偶然」を落とすだけで、「広がりのある偶然」は落とせない
- したがって **P7 で選ばれたこと・合成データで期待どおりに動いたことは、実市場でのエッジの証拠ではない**。広がりのある偶然を落とすのは P8（新しい期間で同じパラメータを試す）と P10（実際の EA の構造でパイプライン全体の偶然の合格率を測る）の役割。P7 はそのための候補を絞る段階にとどまる

|---|---|
| 決定性 | 入力の並び順を変えても（20 通りの並べ替え）、選ばれる候補・順位・ID が完全に同じ |
| **予算超過時の再現性**（R5） | 代表が K を超える入力（同点を意図的に含む: 3 つの物差しがすべて同じ候補の組、平均順位だけ同じ組）で、§3.5-2 の同点処理どおりに決まり、並べ替え・再実行で同じ結果になる |
| **統合順位の手計算**（R5） | 小さな例（代表 4〜6 件）で、層・平均順位・同点処理の結果を手で計算した期待値と一致。最大 DD は小さい方が上位になる |
| **尺度に依存しない**（R5） | 各物差しを定数倍・単調変換しても統合順位が変わらない |
| **DSR が合否を決めない**（R4） | `reason_codes` に DSR 由来のコードがない。DSR の値だけを変えてもゲートの結果は変わらない。DSR の単調変換で選抜が変わらない |
| **近傍の数え方**（R3） | 取引なしの近傍は数えない。破産・ロスカットの近傍は数えて `NEIGHBORHOOD_UNSTABLE`。数えた近傍が下限（2 次元で 4）未満なら `NEIGHBORHOOD_INSUFFICIENT`。グリッドの角は落ちる。取引なしの三角形の境目の候補は、数えた近傍が下限以上なら評価される。P5 の値と並べて記録される |
| ゲート | 孤立した合格点・Peak Ratio > 1.5・近傍の中央値 ≤ 0・Robust Score ≤ 0 が、それぞれ正しい理由コードで落ちる。全ゲートが評価される（最初の不合格で止めない） |
| 代表の選び方 | メドイドが不合格のとき、合格した中で最も近い候補が代表になる。同じ距離なら統合順位、次に candidate_id |
| 予算 | 選ばれるのは K 件以下、同じ領域から 1 件以下 |
| 入力の検査 | ラウンド違い・ブートストラップ不足・Discovery 以外の評価値を拒否 |
| 合格 0 件 | P4 合格 0 件のとき、選抜 0 件・理由 `NO_ELIGIBLE` で正常終了 |
| 冪等・選び直し | 同じ入力の再実行は ALREADY_DONE。設定を変えると別の実行になり `SELECTION_REVISED` |
| 全体の流れ（偽の端末） | P4 合格が出るように調整した合成ラウンドで、足切り → ロバストネス → 統計 → 選抜まで通す |
| P0〜P6 | 既存のテストがすべて通る |
