## P6 の目的（これだけ）

> 「1,044 回試した中から選んだ」ことによる上振れを **DSR** で割り引き、期待値・Sharpe・最大 DD の不確かさを、日次データの自己相関を考慮した**ブロック・ブートストラップの信頼区間**で示す。

P5 と同じく、P6 は**評価値を出すだけで合否は決めない**（判定は P7）。P6 の結果はすべて **Discovery 期間の内側（イン・サンプル）**の値で、アウト・オブ・サンプルの証拠ではない（§5）。

依頼された 5 つの論点（試行回数、ブートストラップの方法、信頼区間の定義、データの独立性、検証テスト）は §2〜§6 に 1 節ずつ書く。

## 1. 調査結果（計画の根拠）

### 1.1 DSR の式と参照実装

| 事項 | 内容 | 確認レベル |
|---|---|---|
| DSR の式（原著） | SR₀ = √V[{ŜR_k}] · ((1 − γ)·Φ⁻¹(1 − 1/N) + γ·Φ⁻¹(1 − 1/(N·e)))、DSR = PSR(SR₀)。γ はオイラー・マスケローニ定数（0.5772…）、V[{ŜR_k}] は**試行間の Sharpe の推定値の分散**（年率化しない） | B（原著 [S-DSR]。SSRN は本環境から取得できず、設計時の確認のまま） |
| R quantstrat `deflatedSharpe`（GitHub braverock/quantstrat のソース） | SR₀ の式（期待最大値の近似）と PSR の部分は原著と同じ。ただし、(a) 試行間の分散に **Sharpe ではなく「純損益の変化率」の分散**を使っている、(b) 出力の `deflated.Sharpe` は **Sharpe × PSR(SR₀)** という独自の値で、原著の DSR（確率）は `1 − p.value` にあたる | **A**（ソース確認） |
| N = 1 のとき | Φ⁻¹(0) = −∞ になるので式が使えない。原著の趣旨（選択がない）から SR₀ = 0、DSR = PSR(0) とする | 原著の趣旨から |

→ **原著の式どおり**に実装する（V は試行間の Sharpe の分散）。quantstrat は「期待最大値の近似」の部分の検算にだけ使い、分散と出力の定義は採用しない。

## 2. 論点 1: DSR の試行回数（N をどう扱うか）

### 2.1 何が問題か

DSR の式の N は、原著では「**実質的に独立な**試行の数」。グリッドの隣り合うパスは強く相関している（P5 の地図で見た「偶然の島」）ので、1,044 本は 1,044 個の独立な試行ではない。

- 生の N（1,044）をそのまま使うと、SR₀（偶然でも出る最大 Sharpe の目安）を**過大に**見積もる → DSR は低めに出る（**保守側**: 偶然の合格は減るが、本物のエッジも見逃しやすい）
- N を小さく見積もりすぎると、DSR が高めに出る（偶然の合格が増える）

### 2.2 選択肢の評価（CLAUDE.md の 5 観点）

| 方法 | 何を測るか | 仮定 | 適合性 | 重複 | コスト | 判定 |
|---|---|---|---|---|---|---|
| **生の N**（`trial_ledger` の戦略ファミリー合計） | 依頼した試行の数 | 試行が独立（実際は違う → 保守側に偏る） | 高い。数え方が明確で、ごまかしようがない | — | 極小 | **判定に使う値（主）** |
| 固有値による実効試行数（参加比 N_eff = (Σλᵢ)² / Σλᵢ²、λ は全パスの日次リターンの相関行列の固有値） | 相関を考慮した「実質的な次元の数」 | 相関行列が安定に推定できる。1,044 パス × 520 日では**パス数 > 日数**で、行列は退化する（推定誤差が大きい） | 中。目安にはなるが、DSR の原著の方法ではない | — | 小 | **参考値として表示するだけ**（判定に使わない） |
| ONC クラスタリング（López de Prado & Lewis 2019）[S-ONC] | 相関でまとまった「戦略の群」の数 | クラスタの品質指標が意味を持つ | 高い（DSR の著者が勧める方法） | — | 中〜大（再帰的なクラスタリング） | **P12 で導入**（設計書どおり。C6） |

### 2.3 シミュレーションで分かったこと（レビュー指摘 2 への回答）

「生の N なら必ず保守的」とは**言えない**。真の Sharpe が 0 の戦略 100 本（各 500 日）から最良の 1 本を選ぶ実験を 2,000 回ずつ行った（`docs/research/p6_simulations/`、シード 20261011）。表は「最良の 1 本が 0.95 以上になった割合」（偶然の合格率。名目は 5%）。

| 戦略の相関構造 | PSR(0) | 生の N の DSR |
|---|---|---|
| 独立 | 99.6% | 0.25% |
| 全体が同じ要因を共有（相関 0.3 / 0.6 / 0.9） | 77% / 50% / 20% | 0.95% / 2.6% / **4.75%** |
| 5 つ・2 つの群に分かれる（群内の相関 0.9 / 0.95） | 50% / 24% | 0% / 0.25% |
| ボラティリティの局面が変わる（相関 0.9） | 20% | 4.5% |
| **日次リターンに自己相関（0.2 / 0.4 / 0.6）＋ 相関 0.9** | 31% / 41% / — | **8.9% / 14.6% / 20.7%** |

読み取れること:
- 戦略どうしの相関が強いほど、生の N の DSR は保守的でなくなり、**「1 本だけ試した場合」の 5% に近づく**（相関 0.9 で 4.75%）。DSR が使う試行間の分散 V[SR] は、全戦略に共通する動きを捉えないため
- **5% を超えるのは、日次リターンに自己相関がある場合**。PSR・DSR の式は日ごとのリターンが独立だと仮定していて、ポジションを数日持ち越す EA（P3 の EA もそう）ではこの仮定が崩れ、Sharpe の推定のばらつきを過小評価する

### 2.4 自己相関の補正（O9、**独自拡張**）

日次リターンの 1 次の自己相関 ρ̂₁ が正のとき、PSR・DSR の標本長 n を、AR(1) 近似の**実効標本数** n* = n·(1 − ρ̂₁)/(1 + ρ̂₁) に置き換えた値も計算する。同じ実験での効果:

| 状況 | 生の N の DSR | 補正した DSR |
|---|---|---|
| 独立 | 0.25% | 0.2% |
| 自己相関 0.2 / 0.4 / 0.6 ＋ 相関 0.9 | 8.9% / 14.6% / 20.7% | **5.1% / 5.15% / 5.1%** |
| 本物のエッジあり（日次 Sharpe 0.12、独立、相関 0.3）の検出力 | 94.8% | 94.5% |
| 本物のエッジあり（自己相関 0.2）の検出力 | 90.2% | 79% |

- **判定に使う DSR は、補正なしと補正ありの小さい方**（ρ̂₁ ≤ 0 なら補正なしと同じ）。両方の値と ρ̂₁・n* を記録する
- これは原著の DSR にはない**独自拡張**（Sharpe の推定誤差を系列相関で補正する考え方は Lo (2002) "The Statistics of Sharpe Ratios" にあるが、ここでは最も単純な AR(1) 近似を使う）。標準の DSR と並べて報告する（CLAUDE.md の約束）
- 限界: AR(1) 近似は 2 次以上の依存（数日にわたる複雑な依存）を完全には補正しない。実データで ρ̂₁ と高次の自己相関を記録し、大きい場合は注記する

### 2.5 決定案（O1）

- **N は生の N**（その戦略ファミリーの `trial_ledger` の合計。今回は 1,044）。取引しないパスも N に含める（C44）
- **V[SR] の定義（レビューでの確認事項）**: 判定する候補と**同じラウンド**（同じ期間・同じ日数）の、Sharpe が計算できたパスの日次シャープ（年率化しない、P4 の C53 と同じ入力）の**標本分散（ddof = 1）**。取引しないパスと破産・ロスカットのパスは V に入れない（§2.6）。期間の違うラウンドの Sharpe は推定の精度が違うので混ぜない。N だけはファミリー全体（保守側）
- **判定に使う DSR = min(標準の DSR, 自己相関を補正した DSR)**（O9）
- 参考として、固有値による N_eff で計算した DSR も表示する（判定には使わない）
- 限界として「相関と自己相関のもとで生の N は常に保守的とは限らない」ことを計画書と CLI の注記に書く。ONC による N_eff は P12
- 設計変更 C7 の更新（O7）は §9 のとおり

### 2.6 破産・計算できない系列の扱い（レビュー指摘 3）

| 候補の状態（P5 の `score_status`） | その候補の Sharpe・DSR・区間 | V[SR] への算入 | N への算入 |
|---|---|---|---|
| `OK` | 計算する | 入れる | 数える |
| `NO_TRADES`（分散 0） | null、理由 `zero variance (no trades)` | 入れない（値がない） | 数える |
| `NOT_COMPUTABLE` | null、理由 | 入れない | 数える |
| `BANKRUPTCY` / `STOP_OUT` | **null、理由 `bankrupt/stop-out: the daily series after the event is not a return distribution`** | **入れない** | 数える |

- 破産を数値で表さない理由: テスター内で破産すると、その後は取引できずエクイティが張り付き、日次リターンは 0 が続く。この系列で Sharpe を計算すると、「破産の日の巨大な損失」と「その後の 0 の並び」の比率しだいで値がいくらでも変わり、**意味のある分布にならない**。破産した候補は P4 の `BANKRUPTCY` ですでに不合格なので、DSR を計算しなくても判定は変わらない
- V[SR] から外す理由: 意味の定まらない Sharpe を入れると、分散が人工的に大きくなる（SR₀ が上がる）か、小さくなる。外す代わりに、**N には数える**ので、試行回数の補正は弱まらない
- 外した件数は、状態ごとに `statistics_execution` に記録する

## 3. 論点 2: ブートストラップの方法

### 3.1 なぜ単純な独立抽出ではいけないか

日次損益には、(a) 前日との相関（ポジションを数日持ち越すと、損益が日をまたいで続く）、(b) **ボラティリティの偏り**（荒れる時期と静かな時期がまとまって来る）がある。1 日ずつ独立に抽出すると、これらが壊れ、ばらつきを**過小評価**する（信頼区間が狭すぎる）。

### 3.2 方法の比較（CLAUDE.md の 5 観点）

| 方法 | 抽出の単位 | 依存を保つか | 弱点 | 判定 |
|---|---|---|---|---|
| 独立（IID） | 1 日 | 保たない | 自己相関・ボラティリティの偏りがあると区間が狭すぎる | **比較用のみ**（テストで「狭すぎる」ことを示す） |
| 移動ブロック（MBB） | 固定長のブロック | ブロック内は保つ | 系列の端の日が選ばれにくい。再標本が定常にならない | 不採用 |
| 循環ブロック（CBB） | 固定長、端を循環でつなぐ | ブロック内は保つ | ブロック長を固定する必要。つなぎ目に人工的な段差 | **感度の確認用**（主と結果が大きく違わないかを見る） |
| **定常ブートストラップ（SB、Politis-Romano 1994）** | 長さが幾何分布に従うブロック | ブロック内は保つ。再標本も定常 | 平均ブロック長の選び方に結果が依存する → Politis-White の自動選択で決める | **主** |

### 3.3 決定案（O2）

- 主は **定常ブートストラップ**（`arch.bootstrap.StationaryBootstrap`）。平均ブロック長は `optimal_block_length` の `stationary` 列（1 未満なら 1）
- 感度の確認として、循環ブロック（`optimal_block_length` の `circular` 列）でも同じ区間を計算して並べる。主と大きく違う場合は注記する
- 限界を明記する: ブロック・ブートストラップが保つのは**ブロック長程度の短い依存**だけ。数か月続く相場の局面（レジーム）の違いや、2 年間に起きなかった出来事は反映されない。区間は「この 2 年間のデータの標本誤差」であり、将来の範囲の予測ではない

## 4. 論点 3: 信頼区間の対象（何を、どの単位で、どう計算するか）

### 4.1 共通の定義

| 項目 | 定義 |
|---|---|
| 再標本化するデータ | 候補の**日次リターン r_t = (E_t − E_{t−1}) / D**（P4 の C53 と同じ。E は日末エクイティ、D は初期資金で一定、E_0 = D）。日次 Parquet から作る |
| 再標本の長さ | 元の日数 n と同じ |
| 反復回数 B | 既定 2,000 |
| 乱数 | `numpy.random.Generator(PCG64(seed))`。シードは実行ごとに記録（既定のシードは実行 ID から決定的に作る） |
| 区間の計算法（O3） | **パーセンタイル法**（`method="percentile"`、両側 90%）。理由: 単純で、統計量の変換に対して不変。BCa はジャックナイフが独立を前提にしていて時系列に合わない。studentized は入れ子のブートストラップで重い |
| 記録 | B、シード、平均ブロック長（SB・CBB）、方法、arch のバージョン、元の推定値、区間の下限・上限 |

### 4.2 対象ごとの定義

| 対象 | 統計量 | 単位 | 区間 | 注意 |
|---|---|---|---|---|
| 期待値 | 日次リターンの平均 | 初期資金に対する 1 日あたりの比率（あわせて × D で口座通貨の金額も表示） | 両側 90%（5%・95%） | パスには取引ごとのデータがないので、**1 取引あたりの期待値は扱わない**（P8 で単一テストの約定から） |
| Sharpe | 平均 ÷ 標本標準偏差（ddof = 1、年率化しない） | 1 日あたり | 両側 90% | 再標本で標準偏差が 0 になった回は数えて記録し、全体の 1% を超えたら区間を「不安定」として null と理由 |
| 最大 DD | §4.3 の手順で再標本ごとに日末エクイティの経路を作り直し、その最大下落幅 | 口座通貨（固定ロットのまま）と、そのときの最高値に対する % | **信頼区間ではなく「再標本化した最大 DD の分布」の 5%・50%・95% 点**（最大 DD は推定したい母数ではなく経路の統計量なので、区間とは呼ばない。上側 95% 点を主に表示） | **日末エクイティの DD** なので、EA がティックごとに追跡した DD（P2 の `equity_max_dd`）より小さく出る。両者は別物として並べて表示し、混同しない。ロット調整後の DD の評価は P9 |

### 4.3 再標本での最大 DD の計算手順（レビューでの確認事項）

1. 再標本のリターン列 r*_1, …, r*_n（定常ブートストラップ。元の日の並びを、ブロック単位でつなぎ直したもの）
2. E*_0 = D、E*_t = D + D·(r*_1 + … + r*_t)（固定ロット・複利なし。C53 の逆算）
3. 最高値 P*_t = max(E*_0, …, E*_t)（**開始時の資金 D も最高値の候補に含める**。初日から下がった場合も DD に数える）
4. DD*_t = P*_t − E*_t、最大 DD = max_t DD*_t、その時点の % = DD*_t ÷ P*_t × 100（P2 の `balance_max_dd_pct` と同じ考え方）
5. E*_t ≤ 0 になる再標本があっても値を消さずにそのまま使い、その割合を「再標本での破産の割合」として記録する（判定には使わない。破産確率の評価は P9）

### 4.4 どの候補に計算するか（O4）

- **DSR は全候補**（計算が軽いので、P4 の合否によらず全部）
- **ブートストラップは、P4 に合格した候補と、P5 の島の代表（メドイド）**を既定にする。全 1,044 候補に 2,000 回ずつ行うのは時間がかかり、合格しない候補の区間は判定に使わないため
- 診断用に `--candidate <cd>` で個別に指定できるようにする（今回は P4 合格が 0 件なので、動作確認では P3 で単一テストと照合した `cd_b94d50a54395ef54` を指定する）

## 5. 論点 4: データの独立性（P8 の OOS 検証と混同しない）

| 決めごと | 内容 |
|---|---|
| P6 が読むデータ | そのラウンドの Discovery 期間のデータ（P3 の `pass_result` と日次 Parquet）**だけ**。新しい期間のデータは読まない。期間がラウンドの期間と一致することをコードで確認する |
| 結果の標識 | P6 の評価値すべてに `sample_role = "DISCOVERY_IN_SAMPLE"` と期間 [from, to) を記録する。stage は `STATISTICS` |
| 意味の限定 | DSR は「イン・サンプルで選んだことによる上振れの補正」で、OOS での成績の証拠ではない。信頼区間も「この期間の標本誤差」で、将来の予測区間ではない。CLI の表示にもこの注記を出す |
| P8 との分離 | P8 の OOS 検証は、**新しい期間で新しく実行した結果**（Holdout Guard を通した単一テスト）だけを使う。P8 は P6 の評価値を OOS の結果として読まない（P8 の計画で、stage と `sample_role` によりコードで拒否する） |
| 試行回数 | OOS 検証の実行は、選んだ候補の確認であって新しい試行ではない。ただし、OOS を見た後にパラメータを変えた場合は、新しい試行として台帳に入れ、その候補には `HOLDOUT_CONTAMINATED` を付ける（設計書 §5.4 の約束。P8 で実装） |

## 6. 論点 5: 検証テスト

### 6.1 既知の合成データでの確認と、事前に決める合格基準（レビュー指摘 1）

200 回の実験では、合格率 5% 付近の推定誤差（標準誤差 約 1.5%）が大きすぎる。**回数と許容範囲を事前に決め**、二項分布の **Clopper-Pearson の 95% 信頼区間**で判定する。シードは固定し、テストに記録する。

| テスト | 設定 | 回数 | 合格基準（事前に固定） | 計画時の試算 |
|---|---|---|---|---|
| **偶然の合格率（大きさ）** | 真の Sharpe 0、100 本 × 500 日。(a) 独立、(b) 共通要因の相関 0.9、(c) 自己相関 0.4 ＋ 相関 0.9、(d) ボラティリティの局面 ＋ 相関 0.9 | 各 2,000 回 | 判定に使う DSR（補正の min）の合格率の **95% 上限 ≤ 7%**（名目 5% ＋ 漸近近似の誤差の許容 2%） | 0.2% / 4.75% / 5.15% / 4.5%（上限はいずれも 6.2% 以下） |
| 選択による上振れの確認 | 同じ 4 つ | 各 2,000 回 | PSR(0) の合格率の **95% 下限 ≥ 15%** | 20〜99.6% |
| 補正の必要性（限界の記録） | (c) で補正なしの DSR | 2,000 回 | 補正なしの合格率の 95% 下限 > 7%（＝補正なしでは基準を満たさないことを示す。満たしてしまったら、テストの前提を見直す） | 14.6% |
| 検出力 | 日次 Sharpe 0.12 の本物のエッジ、独立、相関 0.3 | 2,000 回 | 判定に使う DSR の合格率の 95% 下限 ≥ 80% | 94.5% |
| ブートストラップのカバレッジ | AR(1)（φ = 0.5）、n = 520、真の平均 0（真の Sharpe 0）。名目 90% の区間 | 400 回（B = 499） | 定常ブートストラップの平均・Sharpe の区間が真の値を含む割合が **84%〜96%**。独立抽出は定常ブートストラップより **10 ポイント以上低い** | SB 88.3%、IID 66% |
| DSR の式 | 独立に書いた式（`statistics.NormalDist`）との一致。期待最大値の近似は quantstrat の `maxZ` と同じ式 | — | 1e-12 以内で一致 | — |
| N = 1 | SR₀ = 0、DSR = PSR(0) | — | 一致 | — |
| 最大 DD | 手で計算できる短い系列（開始直後に下がる系列を含む） | — | §4.3 の手順の手計算と一致 | — |
| 再現性 | 同じシード / 違うシード | — | 完全一致 / 変わる | — |

- 判定の不確かさの目安: 回数 2,000・観測 5% のとき、95% 区間の幅は約 ±1%
- 時間がかかるテスト（合計 1 分程度の見込み）は印（`slow`）をつけるが、既定の `uv run pytest` で必ず実行する
- 基準の 7% と 84〜96% は、シミュレーションの結果を見てから都合よく決めたものにならないよう、**この計画の承認時に固定**し、実装後に変えない（変える場合は設計変更として記録）

### 6.2 異常値に対する挙動

| ケース | 期待 |
|---|---|
| 欠損（日次データがない、NaN・無限大） | DSR・区間は null と理由。合格扱いの値は出さない |
| 破産・ロスカット（`score_status = BANKRUPTCY / STOP_OUT`） | §2.6 のとおり、Sharpe・DSR・区間は null と理由。V[SR] に入れず、N には数える。件数を記録 |
| 取引なし（日次リターンがすべて 0） | Sharpe・DSR・区間は null と理由 `zero variance`。N には数える |
| 極端な損益（1 日だけ巨大な損益） | 計算が壊れない（有限の値）。Sharpe の区間が広がる。歪度・尖度の極端な値が PSR/DSR を下げる方向に効く |
| V[SR] = 0（全パスの Sharpe が同じ） | SR₀ = 0（DSR = PSR(0)）として理由を記録 |
| 日数が少ない（ブロック長に対して短い） | 区間を出さず理由を記録（目安: n < 30） |
