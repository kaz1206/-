## 1. 重要指標: エッジがない条件で、候補が選ばれる割合（承認時の指示）

| シナリオ（エッジなし） | 1 件以上選ばれた割合（95% 区間） | 1 回あたりの選ばれた件数（平均・分布） |
|---|---|---|
| B: 偶然の山 ＋ 孤立した尖り 3 つ | **73.0%**（68.9〜76.9%） | 平均 1.12（0 件 135 回、1 件 215、2 件 109、3 件 37、4 件 3、5 件 1） |
| C: 偶然の山だけ | **72.8%**（68.7〜76.7%） | 平均 1.09（0 件 136 回、1 件 217、2 件 118、3 件 23、4 件 6） |

- **エッジがなくても、4 回に 3 回は何かが選ばれる。** 隣どうしの成績が似る「なめらかな偶然の山」は、本物の台地と形で区別できないため
- この値には合否の基準を置かない（P7_PLAN §6.1）。下げる役割は P8・P10 にあり、P7 の閾値を合成データに合わせ込まない
- この値は `rlab select run / show` の表示（既知の限界）に毎回出る

## 3. 代用した部分（限界）

- 合成グリッドには日次リターンがないので、P4 の合格は「スコア > 0.05」、DSR は「スコアの大きさ」（順位だけを使う）、最大 DD は乱数で代用した。本物の P4・P6 を通したときの挙動は、偽の端末の結合テスト（`tests/integration/test_select_run.py`）で確認した
- 2 次元のグリッドだけで確かめた

## 4. そのほかのテスト（すべて合格）

| テスト | 内容 |
|---|---|
| 統合順位の手計算 | 4 件の例で、層・平均順位・同点処理・DOMINATED / NOT_SELECTED_BUDGET が手計算と一致 |
| 最大 DD の向き | 他が同じなら最大 DD の小さい方が上位（大きい方は第 2 層） |
| 同点処理 | Robust Score の順位 → 最大 DD の順位 → DSR の順位 → candidate_id |
| 尺度に依存しない | 各物差しの定数倍・単調変換、DSR だけの単調変換で順位が変わらない |
| 丸め | 1e-13 の差は同点として扱われる |
| 予算超過時の再現性 | 同点を多く含む 40 件を 20 通りに並べ替えても、選抜・順位・理由が同じ |
| 近傍の数え方（R3） | 取引なしは数えない、破産・計算不能は数える、下限（2 次元で 4）、角は不合格、取引なしの三角形の境目は評価される |
| ゲート | 全ゲートを評価（最初の不合格で止めない）、各理由コード、近傍の中央値 ≤ 0 は孤立したピーク |
| DSR が合否を決めない（R4） | ゲートの引数に DSR がない。結合テストで DSR を全部ランダムに入れ替えても、FAIL の候補は変わらない。理由コードに DSR 由来のコードがない |
| 全体の流れ（偽の端末） | 足切り → ロバストネス → 統計 → 選抜。P4 合格ごとに判定 1 行、予算・領域ごとに 1 件、冪等、設定を変えると `SELECTION_REVISED`、P4 合格 0 件で `NO_ELIGIBLE`、入力の検査、`why-not` に選抜の判定も表示 |
| P0〜P6 | 既存のテストはすべて合格（変更はスキーマ番号の確認 6 → 7 と、`why-not` が FILTER の判定だけを見るようにした 1 か所） |
