## 1. 目的と、測らないもの

研究 A は、研究マシンの**本番の判定能力**を測る実験である。そのため、EA と Python の売買の一致（§3.1〜3.4）だけでなく、**合成データから最終判定までの処理が、本番と同じ判定を再現していること**（§3.5）を前提条件にする。

| 測るもの | 中身 |
|---|---|
| **安全性（S）** | 優位性のない価格（H0）で、パイプライン（P4〜P8a）が候補を誤って合格させる割合（**誤合格率**） |
| **検出力（P）** | 優位性を仕込んだ価格（H1）で、パイプラインがそれを合格させる割合（**検出率**）と、どの段階で候補が落ちたか（**段階ごとの生き残り**） |

S と P は別々に測り、別々に報告する。片方の結果で、もう片方を補わない。

**測らないもの・主張しないこと**
- 現実の市場での検出率。結果は常に「この仕様の合成条件では」と限定して書く。2 種類の優位性で結果が近くても、それは**試した 2 種類の合成条件に対して頑健**だという意味で、現実の市場に一般化できることの証明ではない。
- RL_TSMom の収益性。
- 研究 A の目的は合格候補を出すことではない。

## 3. 前提条件の確認（測定の前に、すべて合格させる）

### 3.4 合わなかったとき

- 原因を特定してから直す。**直すのは T1 型（模型）の側**。研究 B で使うのは EA そのものなので、EA を模型に合わせない。ただし EA の不具合が見つかった場合は別で、記録したうえで EA を直し、研究 B の事前登録にも反映する。
- 直した後に比べ方を変える必要があれば、再確認の**前に**新しい定義（t2）として記録する。t1 の未達は消さない（P10 の照合 v1 → v2 と同じ手順）。

### 3.5 判定経路の同等性の確認（合成データ → 最終判定）

研究 A の測定は、速さのためにメモリ上で各段階の関数を呼ぶ。その「つなぎ」（入力の作り方・候補の並べ方・ID の対応）が本番と違えば、本番の判定能力を測ったことにならない。そこで、**同じ合成データを本番の経路にも通し、判定が一致すること**を確かめる。

| 項目 | 内容 |

| 対象 | H0 から 3 ラウンド、H1（E1・s = 1.0）から 3 ラウンド（固定シード。P4 合格や選抜が実際に起きるラウンドを含むようにする。選び方はシードで事前に固定） |

## 4. 合成価格と優位性（実験条件として定義する）

### 4.1 共通の土台（H0）

既存の P10 の価格モデルを、値を変えずに使う（`configs/null_archetypes.yaml` の `price` と同じ値。sigma_bar 0.0022、GARCH α 0.05・β 0.93、t 分布の自由度 5、1 日 6 本、1 足 8 段階、開始価格 1.10）。期待値ゼロのマルチンゲールで、スプレッドの分だけ損をする。

S1（健全性の確認）は P10 と同じ定義（スプレッド控除前の平均損益が 0 から 3 標準誤差以内）。S1 を通っても H0 の証明ではない。

### 4.2 優位性（H1）は「土台に足す成分」として作る

- **価格 = 共通の土台（H0 と同じ乱数・同じボラティリティの動き）＋ 優位性の成分。** 優位性の成分は GARCH の計算の外で足し、ボラティリティの動きは H0 と同じに保つ。
- **共通の乱数:** 検出力のラウンド i の土台は、安全性の測定のラウンド i（i = 1〜400）と同じ乱数から作る。優位性の成分は別のシードで作る。これにより、H0 と H1 の違いは優位性の成分だけになり、ラウンドごとに対にして比べられる。
- **確認（実装のテスト）:** 優位性の強さを 0 にした H1 の経路が、同じシードの H0 の経路とビット単位で一致すること。

| 記号 | 作り方 | 固定する値 |
|---|---|---|
| **E1**（体制の切り替わり） | 1 段階ごとの値動きに、ドリフト m × s_t を足す。s_t は +1／−1 を行き来するマルコフ過程で、平均の持続は 6 か月（756 本） | 持続 6 か月。強さ m は §4.3 で決める |
| **E2**（ゆっくり動くドリフト） | ドリフト μ_t が AR(1) で動く（1 足ごとの係数 φ、半減期 3 か月 = 378 本）。μ_t を値動きに足す | 半減期 3 か月。ドリフトのばらつきは §4.3 で決める |

どちらも、上げと下げが対称で、長期の平均的な向きはない。

**E1 の「平均 6 か月」と E2 の「半減期 3 か月」は実験上の設定値で、EURUSD の現実の性質を示す推定値ではない。** 振り返り 1〜12 か月の範囲の中ほどに優位性が出るように選んだ条件である。

### 4.3 「年率 Sharpe s」の定義（実験条件）

| 項目 | 定義 |
|---|---|
| 基準の候補 | **L = 756 本（6 か月）・H = 18 本** の 1 候補 |
| 指標 | その候補の日次リターン r_t = (E_t − E_{t−1}) / 10,000（本番の `daily_sharpe` と同じ定義）の平均 ÷ 標準偏差 × √252 |
| コスト | スプレッド控除後（スワップ・手数料なし） |
| 算出期間 | 1 本の長い経路（200 年分）。シード固定（E1・E2 で別のシード。測定のシードとも別） |
| 目標 | s = 0.5・1.0・1.5。強さ（m・ドリフトのばらつき）を二分法で決め、目標から ±0.02 以内に入れる |
| 事前に保存するもの | 決めた強さ・シード・200 年での基準候補の実際の Sharpe・**60 候補それぞれの真の Sharpe（同じ算出方法）**・その最大値と、最大の候補のパラメータ。**測定の前に固定する** |
| 意味 | s は実験の条件で、**検出力を保証する値ではない**。基準の候補が Sharpe s でも、ほかの候補の Sharpe は同じとは限らない。検出率は「基準の候補の s」と「60 候補の真の Sharpe の分布」の両方と並べて報告する |

### 5.2 P6 の最大 DD の扱い（s2 で修正）

1. 試運転（§6.4）で、**本番と同じ最大 DD の計算**（ブートストラップ、本番の設定どおり）を使って時間を測る。
2. 本測定の全体の見込み時間が **24 時間以内**なら、その方式で本測定を行う。
3. 計算を速くする工夫（並列化・同じ計算の使い回しなど）は、本番の関数と**同じ入力で同じ出力**になることをテストで確かめた場合だけ使ってよい。
4. それでも重すぎる場合、**代用値を使って先に進めることはしない。** 代用方式の誤差と、判定（P7 の選抜・最終判定）への影響を別に検証し、その結果を添えて**仕様を再レビュー**する。代用方式で測った結果は、本番と同等の判定能力の測定としては扱わない。

### 5.3 「検出できた」の定義と、追跡できる記録

- **検出 = そのラウンドで、P8a を PASS した候補が 1 つ以上ある**（研究 B の判定と同じ単位）。
- 安全性の測定（H0）では、P8a を PASS した候補はすべて誤合格。
- **保存するもの（S・P の全ラウンド・全候補）:** 1 ラウンド × 1 候補を 1 行にして、最終判定まで追えるようにする。

  - 候補: パラメータ、真の Sharpe（§4.3）、Discovery の指標（取引数・日次 Sharpe・PSR など）
  - P4: 判定と理由コード
  - P5: Robust Score、島、メドイド、region_status
  - P6: DSR、最大 DD の 95% 点
  - P7: 判定・理由コード・順位
  - P8a: V0・V1 の指標、p 値、Holm の結果、各ゲート、最終判定
- 価格の経路そのものは保存せず、シードから作り直せるようにする（再現できることを試運転で確かめる）。
- 集計: 段階ごとの合格率（P4 → P7 のゲート → 選抜 → P8a）と、落ちた理由コードの内訳。

- 不一致があれば原因を特定し、**模型の側を直す（EA は変えない）**。直した模型は同じ生データで再判定する（`rlab studya fidelity-check`）。本測定の直前にも、その時点の模型で生データを再判定し、一致しなければ開始しない（§12.6）。

### 12.2 日次エクイティの照合（照合の定義 t2 の #9）
- 一致させた定義（Telemetry.mqh と T1 型で同じ。実装を照合済み）:
  - 日次の境界: ティックのサーバー時刻の日付。
  - 評価時刻: その日の最後のティック。値はそのティックでの EA の売買の前のエクイティ（最終日だけは、テスター終了時の決済の後の値 = 最後のティックの評価額と同じ）。
  - 未決済ポジションの評価: 買いは bid、売りは ask（スプレッド 10 ポイント固定）。スワップ 0・手数料 0。
- 判定: 日付の集合が同じで、**各日の終値エクイティの差が 0.01 USD 以下**（両方とも小数 2 桁で記録）。
- 実行前の確認: 偽の端末での配管テストで、1 日だけ 0.02 USD ずらすと #9 で不一致になることを確認（`tests/integration/test_studya_fidelity.py`）。

通常の 12 本（資金 10,000 USD）ではロスカットが起きないため、**テスト用の資金だけを下げた 3 本**を追加した（ロット 0.10・EA の売買ルール・価格は同じ。どれも模型ではロスカットが 1 回起き、その後は資金不足で新規注文が通らない）。水準は口座の実際の値 30%（§12.8）。

比べる項目（すべて満たして一致。どれか 1 つでも欠けたら一致としない）:
- #2・#4（既存）: 強制決済の時刻（同じ 1 分足）・価格（0.5 ポイント未満）・損益（0.01 未満）。#2 に**理由コード**を追加（模型の SO 決済 ⇔ テスターの DEAL_REASON_SO = 6）。

- #13 通貨換算: テスターの口座通貨 USD・レバレッジ 100・損益通貨 USD・証拠金通貨 EUR・契約サイズ 100,000・ティックサイズ 0.00001・ティック価値 1.0・初期資金 = テスト用資金。証拠金は EUR 建てで、USD への換算は現在の価格（模型: ロット × 契約サイズ × bid ÷ レバレッジ）。この換算が違えば #12 と強制決済の時刻に表れる。
- #14 水準の確認（設定ファイルの `account.stop_out_pct` = 30）: (a) RL_ImportT1 v1.01 が書き出す `RL_T1_account.json` で、ロスカットの方式が ACCOUNT_STOPOUT_MODE_PERCENT・水準が設定値・デモ口座・銘柄の計算方式 FOREX・証拠金の固定額 0・証拠金率（買い・売りの初期）1.0・通貨 EUR/USD。**ファイルがなければ「確認できない」として一致にしない。** (b) 3 本のロスカットの時刻がすべて一致したとき、テスターの実際の水準は「ロスカットした時点の維持率 ≤ 水準 < その前の最低の維持率」の区間の共通部分にある。模型の値で、この区間は約 [28.0%, 30.5%) で、30% を含み 50% を含まないことを確認する（`implied_stop_out_bracket` として記録）。

### 12.4 強さ s の校正（s3-C2 の置き換え、校正版 ca2）
- **経路を連結しない。** 本番の 1 ラウンドと同じ長さ（ウォームアップの後から経路の終わりまで、約 19 年）の**独立な世界 40 本**で、世界ごとに基準の候補（6 か月・18 本）の日次リターンの年率 Sharpe を計算する。
- 目標: 40 本の Sharpe の**平均**が s（0.5・1.0・1.5）に一致するよう、優位性の倍率を二分法で決める（|平均 − s| ≤ 0.005 で停止、0.02 まで許容）。
- 記録: 基準の候補と 60 候補すべてについて、40 本の値そのものと、平均・中央値・標準偏差・最小・最大・平均の標準誤差（標準偏差 ÷ √40）・目標との差。H0（倍率 0）の 60 候補も同じ形で記録。40 本の精度は事前に断定せず、この実測値から不確かさを報告する。
- 固定したもの（本測定の前）: 基礎経路のシード 20261130（世界番号 0〜39、E1・E2 で共通）、優位性のシード E1 20261131・E2 20261132（同じ世界番号）、集計方法 `mean_of_per_world_sharpe`（設定ファイルに記録し、別の値ではコマンドが拒否する）。
- 正式な校正（`results/calibration.json`）は忠実度確認の合格後にだけ実行できる（コマンドが拒否する）。上書きはできない。

### 12.5 価格モデルの検証（s3-C1 の確認、`rlab studya price-check` → `results/price_model_check.json`）
- 1 ステップの**リターン率**（分布・ボラティリティの偏り・まれな大変動）と、価格変動の**絶対幅**を分けて記録する。
- リターン率: 研究 A の基礎の乱数は、P10 の H0 モデル（`robustlab.nulltest.sim.prices`）に同じ乱数生成器を与えたときの増分 ÷ 開始価格と数値で一致すること、価格のパラメータが `configs/null_archetypes.yaml` と同じであることを確認する。4 時間足でのリターンの標準偏差・超過尖度・自己相関（r と |r|）・4 標準偏差を超える割合を、引いた乱数・掛け算型の経路・算術型（P10 と同じ作り方）の経路で並べる。
- 絶対幅: 掛け算型では価格の水準に比例し（p_{t−1}·|r_t|）、算術型では一定（開始価格 ·|r_t|）。S の 1,000 本で、平均の絶対幅（ポイント）とその比、最終価格の分布、算術型で 0 に達する本数を記録する。
- 優位性の強さ 0 で、対応する H0 と同じ価格系列になること（両方の優位性、複数ラウンドでビット単位）。
- 正値性: S の 1,000 本すべて、および校正後の P の 6 設定 × 400 本すべて。P の確認は校正の後に同じコマンドをもう一度実行する（校正のハッシュを記録）。

### 12.6 実施順序と測定の保護
1. 忠実度確認（利用者が MT5 で実行 → `fidelity_t1.json` を Claude が判定）。
2. 合格したら正式な校正（`rlab studya calibrate`）。模型を直した場合は、関係するテスト・忠実度の再判定・校正をやり直す。
3. 価格モデルの検証を校正の後にもう一度（P の経路の正値性）。
4. `rlab studya status` で 3 つの関門と所要時間の見込みを確認し、本測定（`rlab studya measure ALL`）。
- `measure` は、(1) 忠実度 t2 の一致（その時点の模型で生データを再判定）、(2) 同じ設定ファイルで作った ca2 の校正、(3) 同じ設定・同じ校正での価格検証の合格、がすべて揃わなければ拒否する。
- 開始の記録（`<名前>.started.json`）を測定の前に書く。結果がないまま開始の記録が残っている（技術的な失敗）ときは、`--rerun-reason` で理由を書いた場合だけ、**同じ設定・同じ校正・同じシード**で再実行する（設定や校正が変わっていれば拒否）。理由と試行の履歴は結果ファイルにも入る。結果ができた測定は 2 回目を拒否する。
- 所要時間: 試運転の実測（1 ラウンドあたりの秒数）から見込みを出し、24 時間を超える場合は開始せずに報告する（近似値への切り替えはしない）。
- 事前登録した基準で実施し、緩めない。

### 12.7 実装中に見つかった欠陥（結果への影響なし）
- T1 型で、資金を整数で渡すと日次の残高が整数に切り捨てられていた（`np.full` が整数の配列を作るため）。これまでの呼び出しはすべて小数で渡していたので、既存の結果（同等性確認・試運転）には影響しない。ロスカット専用テストの設定を調べる途中で見つけて修正し、単体テストを追加した。

### 12.8 口座のロスカット水準は 30%（2026-10-13、MT5 の設定で判明）
- 見つかったこと: 利用者の MT5 で RL_ImportT1 v1.01 を実行したところ、デモ口座の設定は「割合方式・マージンコール 50%・**ロスカット 30%**」だった。研究 A の模型は 50% を仮定していた（C90 の時点の仮定。§2 の「MT5 と同じ」は水準を確かめていなかった）。50% はマージンコール（警告）の水準で、強制決済は 30%。
- 修正（模型の側。EA は変えない）: `configs/study_a.yaml` の `account.stop_out_pct` を 50 → **30**。ロスカット専用テストのうち、30% ではロスカットが起きなくなる 1 本（H0・126/6・200 USD）を、30% で起きる H0・126/30・200 USD（通常の売買の後にロスカット）に差し替えた。
- あわせて見つけた欠陥: 本測定の経路（`evaluate.run_cell`）が設定の水準を渡しておらず、T1 型の既定値 50% を黙って使っていた（校正と忠実度確認は設定値を渡していた）。既定値をなくし、水準を渡さなければエラーにした。
- 影響: 判定基準・回数・シードは変わらない。ロスカットまでの余裕が広がるので、資金を大きく失いかける回は 50% のときより後で、深い損失で決済される（研究 A の資金 10,000 USD・0.10 ロットでは、ロスカットに近づくのはまれ）。試運転（50% で実行、本測定に数えない）の数字は参考値。判定経路の同等性の確認はもう一度実行する（模型の入力が変わったため）。
- 既存 P10 について（観察のみ、変更しない）: P10 の型モデルも 50% を仮定している。P10 の判定は確定済みで、方針どおりコード・設定・結果は変えない。
