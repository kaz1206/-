### 既知の限界（承認条件 2 に基づき明示する）

1. **AR(2) 型の依存では、どの DSR も基準を満たさない**（保守的な DSR でも 6.30%、上限 7.46%）。補正で 18.85% → 6.30% に下がるが、**5% 水準は保証されない**
2. **補正なしの標準 DSR は、日次リターンに自己相関があると基準を大きく超える**（11〜22%）。ポジションを持ち越す EA ではこれが普通なので、標準 DSR だけを見てはいけない
3. MA(5)（数日にわたる依存）では Newey-West の補正だけでは足りない（6.95%、上限 8.15%）
4. 補正には検出力の代償がある（§2）
5. ここで調べた 8 つの状況以外の依存の形（長い局面、取引の集中など）では、さらに悪い可能性がある

**よって、DSR と各種補正値は警告・順位づけにだけ使い、単独で合否を決めない（C62、承認条件 1）。偶然の合格の最終的な抑止は P8（新しい期間での OOS 検証）と P10（実際の EA の構造を使った帰無仮説テスト）で行う。**

計画時（実装前のシミュレーション）との違い: 補正後の値は計画時より少し良い（例: AR(1) 0.4 の Newey-West 6.6% → 4.85%、MA(5) のブートストラップ SE 7.5% → 5.80%）。ブートストラップの実装（自前 → arch）と乱数の流れが変わったため。AR(2) で全方式が基準を満たさないという結論は変わらない。

### 事前登録した基準を満たさなかった項目（緩めずに記録する）

「選択による上振れの確認」（PSR(0) の 95% 下限 ≥ 15%）が、**共通要因のみ（下限 14.8%）と GARCH（下限 14.9%）の 2 状況で満たさなかった**。

- これは DSR の安全性の基準ではなく、「実験の設定で選択による上振れが実際に起きている」ことを確かめる健全性の確認。上振れ自体は明確に出ている（名目 5% に対して 16.4%・16.5%）
- 実装の誤りではないことを確認した: 実装前のシミュレーションと**同じ乱数の流れ**で動かすと、実装は 20.35% と完全に一致する。別の 6 つのシードでは 18.7% ± 1.0% で、今回の 16.4% は低めに出た回（ブートストラップが乱数を消費するため、流れが変わった）
- 事前登録の約束どおり、基準を緩めることも、通るシードを選び直すこともしない。テストは「この 2 状況が基準を満たさない」ことを記録として確認し（`KNOWN_CRITERION_MISSES`）、状況が変われば知らせる

## 5. そのほかのテスト（すべて合格）

| テスト | 内容 |
|---|---|
| DSR の式 | 標準ライブラリだけで書いた式と 1e-12 以内で一致（N = 2・10・1,044・10⁶） |
| N = 1、V = 0 | SR₀ = 0、DSR = PSR(0)、理由を記録 |
| 自己相関の補正 | 既知の AR(1) 系列で n* と Newey-West のラグ数が式どおり。負の自己相関では n を増やさない |
| 最大 DD | 手計算と一致（開始直後に下がる系列、途中で 0 を割る系列を含む） |
| 区間の計算 | arch の `conf_int(method="percentile")` と完全に一致 |
| 再現性 | 同じシードで完全一致、違うシードで変わる |
| 異常値 | 欠損・NaN・30 日未満・分散 0 は区間を出さず理由。再標本で分散 0 が 1% を超えると Sharpe 区間は「不安定」で null |
| 極端な 1 日 | 計算は壊れない。**巨大な損失の日は PSR/DSR を下げるが、巨大な利益の日は歪度の項で PSR/DSR を上げる**（式の性質。注意として `docs/metrics_definitions.md` に記載） |
| 全体の流れ（偽の端末） | 全候補に DSR か理由、破産・取引なしは V から外して N に数える、ファミリーの N は重複・再実行を二重に数えない、統計は判定（decision）を書かない、冪等、シードを変えると別の実行 |
| P0〜P5 | 既存の 226 件はすべて合格。変更はスキーマ番号の確認 2 か所（5 → 6）だけ |
