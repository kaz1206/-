## 1. 統計・金融工学手法の評価

各手法を、ご指定の 5 観点（何を測るか / どの仮定に依存するか / 今回の問題に適しているか / 他手法と重複しないか / コストに見合うか）で評価し、採否と実装方法を決めた。

### 1.1 PSR（Probabilistic Sharpe Ratio）・MinTRL [S-PSR]

| 観点 | 評価 |
|---|---|
| 何を測るか | 観測された Sharpe が基準値 SR* を上回る確率。歪度と尖度を考慮する。MinTRL は、その確信度に達するのに必要な標本長 |
| 式（原著） | PSR(SR*) = Φ( (ŜR − SR*)·√(T−1) / √(1 − γ̂₃·ŜR + (γ̂₄−1)/4·ŜR²) )。ここで ŜR は**年率化しない観測頻度の Sharpe**、γ̂₄ は（超過尖度ではなく）尖度。MinTRL = 1 + [1 − γ̂₃·ŜR + (γ̂₄−1)/4·ŜR²]·(z_α / (ŜR − SR*))² |
| 依存する仮定 | 収益の定常性と、緩い独立性。推定量の漸近正規性。系列相関が強いと過信につながる |
| 今回への適合 | 高い。v0.1 の「取引数の統計的十分性ルール」（n ≈ (z/s)²）は、**MinTRL を粗く独自に再発明したもの**だったので置き換える |
| 重複 | DSR は PSR の特殊形（基準値 = SR₀）。計算部品を共有する |
| コスト | 極小（数式のみ） |
| **判定** | **MVP 採用**。数式が単純なので自前で実装し、原著の数値例と R PerformanceAnalytics [S-PA-R] を検算の基準（テストオラクル）にする |

### 1.2 Deflated Sharpe Ratio [S-DSR], [S-ONC]

| 観点 | 評価 |
|---|---|
| 何を測るか | 多数の試行から最良を選んだことによる選択バイアスと、非正規性を補正したうえで、Sharpe が有意かどうか |
| 式（原著） | SR₀ = √V[{ŜR_n}] · ((1−γ)·Φ⁻¹(1 − 1/N) + γ·Φ⁻¹(1 − 1/(N·e)))（γ はオイラー・マスケローニ定数）、DSR = PSR(SR₀) |
| 依存する仮定 | 期待最大値の近似は、**N 個の独立・正規な試行**が前提。V[SR] は**試行間の Sharpe の分散**（年率化しない値）。N は**実効的に独立な**試行数 |
| 今回への適合 | 高い。MT5 の最適化は大量試行そのもの。ただしグリッドの各パスは強く相関するため、N の扱いが要になる |
| 重複 | PBO・SPA と目的が一部重なる（いずれも選択バイアス）。DSR は「選ばれた 1 候補の Sharpe」を割り引くもので、手続き全体を診断する PBO とは役割が違う |
| コスト | 式は低コスト。V[SR] の正確な算出には全パスの日次損益が必要（Telemetry Frames） |
| N の扱い | MVP は生の N（保守側）。Phase 2 で **López de Prado & Lewis (2019) の相関クラスタリングによる実効試行数 [S-ONC]** を採用する（v0.1 で書いた「階層クラスタ数等」の独自案は撤回） |
| **判定** | **MVP 採用**（自前実装・小さい）。v0.1 の「V[SR] は MT5 のパス別指標で近似」は維持するが、MT5 の Sharpe は定義が不明なので、**Telemetry Frames 導入までは DSR を参考値（WARN 止まり）とし、FAIL 判定には使わない**に変更 |

### 1.3 Probability of Backtest Overfitting（CSCV） [S-PBO], [S-PBO-R], [S-PBO-CRIT]

| 観点 | 評価 |
|---|---|
| 何を測るか | 「IS で最良だった構成が、OOS では中央値未満に沈む確率」。**個別候補ではなく、選抜手続き（ラウンド）の過学習度**を測る |
| アルゴリズム | T×N の損益行列を S 個（偶数・T を割り切る）のブロックに分け、C(S, S/2) 通りの IS/OOS 分割それぞれで「IS 最良の OOS 相対順位」を logit 化する → PBO = logit ≤ 0 の割合。性能劣化・損失確率・確率優位も同時に出る |
| 依存する仮定 | 全試行の損益系列が揃っていること（**試行行列に含まれない試行は見えない**）。ブロック間の交換可能性。時系列依存を保存するという主張には異論がある [S-PBO-CRIT] |
| 今回への適合 | 中〜高。MT5 最適化ラウンドの「最良パスを選ぶ」行為がまさに対象。ただし本基盤の Selector は argmax ではなく Robust Score なので、標準の PBO は「単純最良選択の過学習度」を測ることになる |
| 重複 | DSR（個別候補の割引）とは補完関係。SPA/StepM（有意性検定）とは問いが違う |
| コスト | 中。全パスの日次損益行列（Telemetry Frames）が前提 |
| 既存実装 | R `pbo` 1.3.5（MIT、ソース確認済み）。Python の `pypbo` は PyPI 未登録・テスト未整備なので依存先にしない |
| **判定** | **Phase 2 採用**。CSCV 本体は小さいので、**R `pbo` のアルゴリズムに忠実に移植**し、同じ入力で R `pbo` と数値が一致することを回帰テストにする（rpy2 で R に依存させるより保守しやすい）。用途は**ラウンド単位の診断ゲート**（PBO が高いラウンドは、そこから出た候補全体に WARN を付ける）。拡張案「CSCV の中で本基盤の Selector を回す」は**本基盤独自の拡張**として明記し、標準 PBO と並べて報告する |

### 1.4 White's Reality Check / Hansen's SPA / Romano-Wolf StepM / MCS [S-WHITE], [S-HANSEN], [S-RW], [S-HLN], [S-ARCH]

| 観点 | 評価 |
|---|---|
| 何を測るか | RC/SPA: 「k 個のモデルのうち、ベンチマークを上回るものが**少なくとも 1 つある**か」の検定。StepM: 「**どのモデルが**上回るか」を FWER を制御して特定する。MCS: 最良モデル群の信頼集合 |
| 依存する仮定 | 損失差の系列が定常で弱従属であること。ブロックブートストラップのブロック長が適切であること。SPA は劣後モデルを再中心化から外す点で RC より検出力が高い（Hansen） |
| 今回への適合 | 中。ベンチマークを「取引しない（損益 0）」とすれば、「最適化ラウンドに本物のエッジを持つ候補があるか」を検定できる。**StepM は候補ごとの判定**なので、本基盤の候補選抜と相性が良い |
| 重複 | **RC は独立した機能として実装しない**。arch の `SPA` は docstring で「SPA は Reality Check / Bootstrap Data Snooper としても知られる」と明記しており、3 種類の p 値（upper = 再中心化なし、consistent、lower）を返す。RC は SPA の特殊ケースとして同じ実装から得る（どの設定が RC に対応するかは Hansen (2005) の整理に従い、実装時に数値で確認）。DSR/PBO とは問い（検定か割引か診断か）が違う |
| コスト | 低（arch を使えば数十行）。ただし全パスの日次損益が必要 |
| 実装上の注意 | arch の入力は**損失（loss）**。収益の場合は符号を反転して渡す。**v8.0.0 と main で studentize の挙動が違う**ので、バージョンを固定し、結果にもバージョンを記録する |
| **判定** | **Phase 2〜3 採用（arch を使う。自前実装しない）**。優先順位は StepM（候補ごとの判定）＞ SPA（ラウンド単位）。MCS は不採用（予測モデル比較向けで、本基盤の問いとずれる） |

### 1.5 Bootstrap / Monte Carlo [S-SB], [S-PW], [S-ARCH]

| 観点 | 評価 |
|---|---|
| 何を測るか | 標本の偶然性による期待値・Sharpe・DD・破産確率の分布 |
| 依存する仮定 | iid リサンプリングは独立性が前提（連敗の塊を壊し、DD を過小評価する）。ブロック系は弱従属・定常が前提。**レジーム変化（非定常）は再現できない** |
| 今回への適合 | 必須（リスク評価と資金配分の根拠） |
| 方法の確定 | 日次損益: **Stationary Bootstrap（Politis-Romano 1994）＋ブロック長の自動選択（Politis-White 2004、Patton ら 2009 の補正）**。arch の `StationaryBootstrap` と `optimal_block_length` を使う。v0.1 の「自己相関から自動選択、または既定 5〜20 日」という独自案は撤回。取引単位のリサンプリングは補助（独立性が成り立つ戦略に限る） |
| ポートフォリオ | 複数 EA の日次損益を**同じ日付のブロックでまとめてリサンプル**（行ごとにリサンプル）。arch のブートストラップは 2 次元配列を行単位でリサンプルできるので、これで同時点の相関構造が保たれる |
| コスト | 低（既存ライブラリ） |
| **判定** | **MVP 採用（arch を使う）**。乱数シードは必ず記録する |

### 1.6 Walk-Forward Analysis [S-PARDO], [S-AFML]

| 観点 | 評価 |
|---|---|
| 何を測るか | 「定期的に再最適化する」という**手続き**の頑健性。WFE（OOS 成績 / IS 成績）は Pardo の指標 |
| 依存する仮定 | 窓の長さ・ステップの選び方が結果を大きく左右する。得られる OOS 経路は 1 本だけなので、分散が測れない（CPCV 側からの批判 [S-AFML]） |
| 今回への適合 | 低〜中。要件は「固定パラメータで、検証期間ごとに再最適化しない」なので、評価対象が違う |
| 重複 | 固定パラメータの複数期間検証（⑦）とは目的が違い、重複しない |
| コスト | 高（窓ごとに MT5 で最適化） |
| **判定** | **将来・別トラック（変更なし）**。実装する場合は Pardo の WFE を使う。0.5 や 0.3 といった閾値は二次情報なので、原著で確認するまで採用しない |

### 1.7 CPCV（Combinatorial Purged Cross-Validation） [S-AFML], [S-SKFOLIO-CPCV]

| 観点 | 評価 |
|---|---|
| 何を測るか | 学習する手続き（主に ML モデル）の OOS 性能分布（複数の経路） |
| 依存する仮定 | ラベル区間の重なりを purging で、系列相関を embargo で除く。**各分割で学習（＝ MT5 では再最適化）が必要** |
| 今回への適合 | 低。固定パラメータを評価する本基盤では、各分割で MT5 最適化を組合せ数だけ回すことになり、費用に見合わない。「組合せ分割で過学習を測る」という狙いは、既存試行の再利用で済む CSCV/PBO がすでにカバーしている |
| 重複 | PBO と狙いが重なる |
| **判定** | **不採用（ML 型 EA を導入するまで保留）**。導入する場合も自前実装せず、skfolio の `CombinatorialPurgedCV` を使う。ただし embargo の考え方は ⑦/⑧ の期間分割に**すでに取り入れている**（v0.1 §7.1） |

### 1.8 Haircut Sharpe（Harvey-Liu） [S-HL], [S-QUANTSTRAT]

| 判定 | **不採用（DSR と重複）**。Bonferroni/Holm/BHY の補正と、試行間相関の仮定に依存する。DSR は非正規性を扱え、V[SR] を実データから取れるので、DSR に一本化する。R quantstrat の `haircutSharpe` を検算用に任意で使う程度 |
|---|---|

### 1.9 Kelly 基準・資金配分 [S-KELLY], [S-MTZ], [S-RCK]

| 観点 | 評価 |
|---|---|
| 何を測るか | 長期の対数成長率を最大にするベット比率 |
| 依存する仮定 | **分布（特に平均）が既知**であること。実際には平均の推定誤差の影響が支配的（平均:分散:共分散 ≈ 20:2:1、対数効用では最大 約 100:3:1 [S-MTZ]）。フル Kelly は短期のリスクが非常に大きい |
| 既存の解決策 | (1) Fractional Kelly（現金と混ぜる）[S-MTZ]。(2) **Risk-Constrained Kelly（RCK）**: 「資産が α まで落ちる確率 ≤ β」という制約の下で成長率を最大化し、凸近似で解く。**同じ DD リスクなら Fractional Kelly より成長率が高い**と報告されている [S-RCK] |
| 今回への適合 | v0.1 の「min(f_kelly_adj, f_DD, f_cap)」は、**単一 EA については RCK の問題を直接解いたものと同等**であることを確認した。単一 EA なら成長率は f について凹で、DD 制約は f が大きくなるほど厳しくなる（単調）ので、最適解は min(無制約の Kelly 解, 制約を満たす最大の f) になる。したがって独自の発明ではなく、RCK の 1 変数版として位置付け直す |
| 制約定義の差 | RCK の原著は「**初期資産からの**下落確率」に制約を置く。本基盤は「**ピークからの** DD（peak-to-trough）」で制約する（実運用の停止判断に直結するため）。この違いを明記し、MC で直接評価する（RCK の凸近似は使わない） |
| 推定誤差 | μ の信頼下限（μ_LCB）を使い、さらに分数を掛けると、保守性を二重に掛けることになる。**μ_LCB は推定誤差、分数はモデル誤差（非定常性）への備え**と役割を分け、既定値は分数 0.5（μ_LCB 使用時）とする。両方とも記録する |
| 複数 EA | v0.1 で「将来」とした `multi_kelly`（Σ⁻¹μ）と「全体スケール係数」は、**RCK の多資産版（cvxpy による凸最適化）**に置き換える（将来）。Σ⁻¹μ は推定誤差に極めて弱いので（[S-MTZ] の 20:2:1 が当てはまる）、単独では採用しない |
| **判定** | **MVP: 1 変数の RCK（MC で DD 制約を評価）＋ μ_LCB ＋ 分数**。将来: 多資産 RCK（cvxpy） |

| 問い | 担当する手法 | 単位 |

## 2. MT5 / MQL5 仕様の確認結果

### 2.1 確定した事項（設計に反映済み）

| 事項 | 内容 | 根拠 |
|---|---|---|
| Python API にテスター機能はない | 5.0.6231 の公開関数にテスター関連は存在しない | [S-MT5PY] **A** |
| Python API は Windows 専用 | ホイールは win_amd64 のみ（Python 3.6〜3.14） | [S-MT5PY] **A** |
| ロット ↔ 金額換算は API に任せる | `order_calc_profit` / `order_calc_margin` / `symbol_info`（volume_min/step）がある。**ティック価値からの自前換算はしない**（v0.1 §12.4 を変更） | [S-MT5PY] **A** |
| 単一テストのレポートは HTML/XLSX、最適化は XML | 単一テストを構造化データで取るなら Telemetry が主経路（v0.1 の方針で正しかった） | [S-MT5REPORT] B |
| テスターイベントは最適化時のみ | `OnTesterInit/Pass/Deinit` と Frames は単一テストでは使えない。**単一テストではファイル出力が必須** | [S-MQL5BOOK-TESTER] B |
| 遅延フレーム | `OnTesterDeinit` で最後に `FrameNext` ループを回して回収する | [S-MQL5BOOK-FRAME] B/C |
| テスター内のファイル出力先 | 既定はエージェントのサンドボックス。`FILE_COMMON` で共通フォルダ。**複数エージェントが同じファイル名に書くと衝突する** → ファイル名にジョブ ID とパス番号を含める | [S-MQL5BOOK-FILES] B |
| `ShutdownTerminal` は 2 種類ある | `[Tester]`（テスト終了後に終了）と、`[StartUp]`（build 4230 以降、スクリプト実行後に終了・終了コードを返す） | [S-MT5START], [S-MT5B4230] B |
| カスタムシンボル | テスターで使える。同じ名前でも履歴が異なりうるので、名前に版やハッシュを含める | [S-MT5CUSTOM] B |

### 2.2 既知の落とし穴

- `[Tester]` 設定で端末は起動するが、テストが始まらないという報告がある [S-FORUM-BATCH]。完了検知を「プロセス終了」だけに頼らず、Telemetry 完了マーカーと照合する v0.1 の設計で検出できる。さらに「**起動後 N 分以内にテスターログに開始行がなければ失敗**」という開始検知を追加する。
- build 6061 で `Optimization=3`（全銘柄モード）の XML が空になるという報告がある [S-COMM-6061]。本基盤はモード 3 を使わない。また、レポートの行数と期待パス数の照合（v0.1 §14.4）を必須にする。
