## 3. 露出と多重検定の申告

- 新しい EA は新しい「家族」なので、基盤の露出台帳と試行回数は家族ごとに 0 から始まる。
- ただし研究者（私たち）は、移動平均の交差の結果を通じて EURUSD 2008〜2013 年の値動きをすでに見ている。グリッドの範囲はその結果を見ずに、各手法の一般的な期間から決めた（申告）。
- **手法を 4 つ試すこと自体が多重検定になる。** 1 つの研究の偶然の合格率が小さくても、4 つ試せばおよそ 4 倍になる。合格者が出た場合は「4 手法中 1 つ」と報告する。

## 4. 進め方と止まる条件

- EA のコピーとコンパイル: `scripts/install_eas.py`。**コンパイルエラーが出たら止めて相談**（EA を直すのは結果を見る前なので可。直した内容は記録する）。
- P1〜P7: `scripts/run_pipeline.py` で 3 研究を続けて実行。P1 が失敗・警告あり・履歴不足なら、その研究は止まる（ほかの研究は続く）。
- P7 で 0 件の研究は、そこで終了（P8a の診断は行わない）。
- P7 で選ばれた研究は、その研究の検証計画を診断ではない計画としてロックして P8a を実行する（別の手順書で渡す）。
- **P8a で PASS が出たら、P8b の前に必ず止める。** その手法の P10 の型（帰無仮説のシミュレーション）がまだないので、まず型を作って偶然の合格率を測る。トレンドの A1 型を別の手法に流用しない。
- P9 は P8a の PASS がある場合だけ。

## 5. 結果の読み方

trend v1・v2 と同じ。P4・P7 の合格は利益の予測ではなく、P7 の選抜は優位性の証拠ではない。P8a の不合格は「証拠不足」で、優位性がない証明ではない。EA の単体の成績（P1）は 1 候補の 1 回の結果で、判定ではない。

## 6. 既知の限界

1. 3 本の EA は今回新しく書いたもので、**実機でのコンパイル・動作は未確認**（模擬端末は MQL5 を実行しない）。設定の流れは模擬端末で P1〜P7 まで通ることを確認した（2026-10-12）。
2. 3 手法とも P10 の型がない。合格者が出たときに型を作る。
3. 1 市場・1 時間足だけの検証。トレンドフォローは複数市場に分散して使うのが一般的で、1 市場では成績が弱く出やすい（trend v2 の観察と一致）。
4. 平均回帰は損切りがないため、破産・ロスカットが起きうる。起きた候補は P4 で失格になり、その近傍も P7 で失格になる（設計どおり）。
